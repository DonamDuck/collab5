# 활동·콜라보 30건 확장 + 5건씩 더보기 — 설계

날짜: 2026-08-10 · 백로그 B04 승격 · 대표 결정 08-09~10

## 한 줄

활동·콜라보 상한을 **5 → 30**으로 열고, 소개서에선 **5건씩 끊어 보여준다.**
순서는 **사장님이 직접 정하고**, AI 크롤은 **콜라보를 최신순으로** 채워준다.

## 왜 지금인가 (실측, 08-09)

prod 활성 16곳 중 **8곳이 이미 5칸을 다 채웠다**(콜라보 5/5 = 4곳, 활동 5/5 = 2곳).
게다가 컨시어지 보강 스킬은 후보를 **활동 10·콜라보 10**으로 뽑아놓고 5개만 넣고 있었다 — **매번 절반을 버려왔다.**
즉 이건 "언젠가"가 아니라 **이미 손실이 나고 있는 천장**이다.

> 콜라보 이력은 그 브랜드의 **자산**이다. 많이 쌓인 곳일수록 지금 구조에서 손해를 본다.

## 지금 상태 (건드릴 곳이 좁다)

- **상한은 등록 폼에만 있다** — `register/page.tsx`의 `length >= 5` 2곳 + `length < 5` 2곳.
  DB에도 소개서 화면에도 제한이 없어서, 숫자만 바꾸면 30건이 그대로 저장되고 그려진다.
- **저장 부담 없음** — 사진 366장이 **전부 Storage URL**(base64 0장). 브랜드 한 곳의 사진·활동·콜라보 합이 **7~8KB**.
  30건이면 20KB대. 예전 base64 시절이었으면 이 작업이 훨씬 무거웠을 것 — 사진 이전이 여기서 값을 한다.
- `CollabHistory.year`는 **이미 있고**, 주석에 *"최신순 정렬용"*이라 적혀 있는데 **정렬하는 코드가 없다.** 의도만 남고 배선이 안 된 상태.
- `Activity`엔 시간 정보가 **없다**(title·desc·photos·link).

## 결정 사항

| 항목 | 값 | 근거 |
|---|---|---|
| 활동 상한 | **30** | 현재 최대 5건의 6배. 무제한은 실수(붙여넣기 폭주)를 아무도 못 막는다 |
| 콜라보 상한 | **30** | 위와 동일 |
| 소개서 초기 노출 | **5건** | 지금 화면 그대로 = 첫인상 불변 |
| 더보기 증가폭 | **+5건** | 대표 확정. 30건이면 더보기는 최대 5번 |
| **DNA 입력 상한** | **7건** | 화면 상한과 **분리한다**(아래 §DNA) |
| **인쇄본(A4)** | **7건** | 지류는 요약이다. 30건이면 몇 장이 된다 |
| 순서 | **사장님 수동** | 규칙이 하나뿐이라 설명이 필요 없다 |
| AI 크롤 초기 순서 | **콜라보만 최신순** | 활동은 재료도 개념도 없다(아래 §정렬) |

## ① 상한 — 상수로 뽑는다 (숫자를 흩뿌리지 않는다)

```ts
// src/lib/limits.ts (신설)
export const MAX_ACTIVITIES = 30;
export const MAX_COLLABS = 30;
```

🚨 **이게 이 작업의 첫 번째 함정이다.** 지금 상한 판정이 **네 곳**에 흩어져 있다 —
「추가」 버튼의 `>= 5` 2곳, AI 힌트 주입의 `< 5` 2곳. 그중 하나는 코드 주석에
*"⚠️ 상한(5)과 같아야 한다"* 라고 **사람에게 부탁하는 형태**로 남아 있다.
**부탁은 지켜지지 않는다** — 과거에 "개수 상한을 한쪽만 고쳐" 반대 방향으로 재발한 적이 있다.
→ **네 곳 모두 상수를 참조**하게 바꾸고, 상수 파일에 "여기만 고치면 된다"를 명시한다.

## ② 등록 폼 — **지금 방식 그대로** (대표 지시 08-10)

`＋ 활동 추가` 버튼을 누르면 **빈 입력 폼 1개**가 붙는 현재 동작을 유지한다. 상한만 30으로.
- **새 항목은 맨 뒤에 붙는다** — 앞에 붙으면 사장님이 맞춰둔 순서가 매번 흐트러진다.
- 순서 바꾸기는 각 카드의 **↑↓ 버튼**. (드래그는 모바일에서 어렵다 — 우리 사용자는 폰이 기본)
- 새로 한 콜라보를 앞세우는 건 흔한 동작이라 **「맨 위로」 버튼**을 하나 둔다(클릭 1번).

⏳ **열어두는 것**: 항목이 20건을 넘으면 세로로 늘어선 폼이 길어져 편집이 힘들어진다.
그때 **6번째부터 한 줄로 접기**를 다시 꺼낸다. 지금은 최대 9건이라 이르다.

## ③ 소개서 화면 — 5건씩 더보기

```
[활동 카드 1~5]
──────────────
        활동 12건 중 5건 · 7건 더 보기 ▾
```

⭐ **구현 방식 = 서버에서 전부 그리고, 6번째부터 CSS로 숨긴다.** (렌더 자체를 자르지 않는다)

이유가 셋이다.

1. 🔍 **검색엔진이 읽는다.** 08-09에 소개서를 구글·네이버에 열었다. 클라이언트에서만 그리면
   **접힌 항목이 서버 HTML에 없어서 통째로 색인이 안 된다** — 콜라보 이력을 자산으로 만들자면서
   검색에는 5건만 내놓는 꼴이 된다.
2. 🖼 **사진은 그래도 안 받는다.** `display:none` 안의 `loading="lazy"` 이미지는 브라우저가
   뷰포트 밖으로 보고 요청하지 않는다. 즉 **SEO는 얻고 트래픽은 안 낸다.**
3. 🖨 **인쇄가 공짜로 풀린다.** print 미디어쿼리로 8번째부터 숨기면 §인쇄본 7건이 그대로 성립한다.

- 활동·콜라보는 **각각 독립**으로 센다(활동을 펼쳐도 콜라보는 5건 그대로).
- 접힌 게 없으면 더보기 줄 자체를 그리지 않는다.

## ④ DNA 입력 상한 7 — 화면과 **분리**한다

`brandDigest`가 지금 활동·콜라보를 **전부** 넣는다(상한 없음). 화면 상한만 풀면
**AI 입력이 조용히 따라 부푼다** — 리포트 원가에서 입력이 차지하는 몫이 작지 않다.

```ts
// collab-report.ts brandDigest
m.activities.slice(0, DNA_ITEM_LIMIT)      // 7
m.collabHistory.slice(0, DNA_ITEM_LIMIT)   // 7
```

✅ **지금 데이터에선 비용이 0이다.** 현재 최대가 활동 5·콜라보 5라 **7로 자르면 결과가 같다**
→ 다이제스트 문자열 동일 → `input_hash` 동일 → **DNA 재생성 없음.** 나중에 8건째를 넣는 브랜드부터만 갈린다.

⚠️ **"많이 등록 = 리포트가 좋아진다"는 자동으로 성립하지 않는다.**
리포트를 만들지 말지 가르는 건 개수가 아니라 **서로 다른 축(type)이 4개 이상인가**다.
같은 성격의 워크숍 20개를 넣어도 축은 그대로다. 등록 확대는 **재료의 폭**을 넓히는 일이지
그 자체가 품질 보증은 아니다 — 보강할 때 축을 늘리는 원칙은 그대로 간다.

⏳ **7이 맞는 숫자인지는 실측 대상**이다. 8건 이상인 브랜드가 생기면 A/B로 5·7·10을 비교한다.

## ⑤ 정렬 — 콜라보만 최신순, 활동은 그대로

**콜라보**: `year` 내림차순. 필드는 이미 있고 주석에 정렬용이라 적혀 있는데 **배선만 없다.**
AI 크롤이 채운 결과를 폼에 넣기 전에 정렬한다. 연도가 없는 항목은 뒤로.

**활동**: 시간 정보가 없고, **개념적으로도 최신순이 안 맞는다.**
우리 규칙상 활동은 *"반복되는 것만 — 정기 프로그램·대표 메뉴·상시 서비스"*이고 일회성은 콜라보로 보낸다.
즉 활동은 **"지금도 하는 일"**이라 최신이라는 축이 없다(매주 여는 클래스에 연도를 붙이면 이상해진다).
→ **크롤이 준 순서(대표성 순)를 그대로 둔다.**

⏳ 활동에 연도 칸을 만드는 건 **별건**으로 남긴다(스키마·폼·프롬프트가 같이 움직임).

## ⑥ 계측

| 이벤트 | 파라미터 | 무엇을 알려주나 |
|---|---|---|
| `activity_more` | `page`(2,3,4…) | 뒤 층을 실제로 보는가 |
| `collab_more` | `page` | 〃 |

**아무도 2페이지를 안 누르면 뒤 층은 창고**라는 뜻이다. 그러면 다음 결정은
"더 늘리기"가 아니라 "앞 5개를 더 잘 고르기"가 된다. 이 숫자가 그 갈림길의 근거다.

## 안 하는 것 (의도적으로)

- **폼 접기** — 20건 넘을 때 재론(위 §②)
- **보는 사람에 따라 순서를 바꾸기** — DNA로 "이 쌍에 맞는 활동"을 위로 올리는 건 우리만 할 수 있는
  동작이지만, 소개서가 사람마다 달라 보이는 혼란과 비용이 크다. **방향으로만 남긴다.**
- **활동 연도 칸** — 별건

## 작업 순서

1. `lib/limits.ts` 신설 + 폼 4곳을 상수 참조로 (상한 30) — 이것만으로 6번째 등록이 열린다
2. 소개서 더보기(서버 렌더 + CSS 숨김 + print 7건) + 계측
3. `brandDigest` 7건 컷
4. 크롤 결과 콜라보 `year` 내림차순 정렬
5. 폼 ↑↓·「맨 위로」

1번이 끝나면 **그날부터 컨시어지가 버리던 절반을 넣을 수 있다.** 2~5번은 그 뒤 순서대로.
