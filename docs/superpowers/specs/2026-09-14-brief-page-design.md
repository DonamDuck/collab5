## 한 줄

지금 노션으로 드리는 **브리프를 collab5 페이지로** 만든다. 작업·퇴고는 노션에서 계속하고,
**발행본만 사이트로** 옮긴다. `/my`에 「요약 보고서」 카드를 달아 **고객이 다시 찾을 수 있게** 한다.

## 왜 이 모양인가 — 대표 확정 사항

| 결정 | 값 | 근거 |
|---|---|---|
| 누가 보나 | **브리프 주인만** | 대표 확정(09-14). 지금 노션은 링크만 알면 누구나 본다 |
| 계정 연결 | **대표가 매번 수작업** | 대표 확정. 자동 매칭 안 만든다 |
| 표 | **살린다** | 대표 확정. 확정 브리프 7건에 표가 **34개**(§실측) |
| 표 종류 | **한 가지** | 대표: *「표 하나 이쁘게 만들자」*. 실측이 뒷받침한다(§실측) |
| 작업 위치 | **노션 유지** | 대표 퇴고가 최종본을 만든다(09-14 라파의 숲에서 실증) |
| 동기화 방향 | **노션 → 사이트 한 방향** | 양방향은 09-14에 겪은 부분 치환 충돌을 사고로 만든다 |

## 🚨 이 기능의 존재 이유가 된 한 가지

지금 브리프는 **DM으로 링크를 한 번 드리면 끝**이다. 고객이 나중에 다시 읽으려면 카톡을 뒤져야 한다.
`/my`에 붙으면 계정에 남고, **읽고 나서 바로 소개서 수정으로 이어진다.**
🔗memory [[daepyo-wants-machines-not-reports]]의 축에서 ⭕ — 「다음 행동이 붙는다」.

## 📏 실측 — 표를 몇 형태로 쓰고 있나 (09-14, 확정 브리프 7건)

`lmp작업실 · 고요 · 도시의바깥생활 · 라파의숲 · 방혜리 · 콜마페 · 터`

| 무엇 | 값 |
|---|---|
| 총 표 | **34개** (브리프당 평균 4.9개) |
| 열 수 | 2열 **14** · 3열 **16** · 4열 **4** |
| 행 수 | 최소 1 · 중앙값 **5** · 최대 **19** |

**머리글 조합을 세니 층이 둘로 갈렸다.**

| 머리글 | 횟수 | 정체 |
|---|---|---|
| `항목 / 내용` | 6 | **카드 표** — 스킬 §📐1️⃣ 고정 형식 |
| `(빈칸) / 무엇 / 숫자` | 6 | **숫자 표** — 스킬 §📐2️⃣ 고정 형식 |
| 나머지 22종 | 각 1 | **관찰 안의 실물 표** — 브랜드마다 다르다 |

⭐**그래서 표 «종류»를 여러 개 만들 이유가 없다.** 필요한 건 하나뿐이다 —
**2~4열 · 머리글 한 줄 · 열마다 정렬 지정.**
📌숫자 표의 「숫자」 열은 **오른쪽 정렬 + 굵게**가 스킬이 정한 형식이라 정렬 옵션이 꼭 필요하다.
⚠️**19행짜리가 하나 있다** — 모바일에서 가로 스크롤 컨테이너가 필요하다.

## ⛔ 매거진에 얹으면 안 되는 이유

처음 후보는 「매거진 템플릿 재사용」이었는데 **그대로는 깨진다.**

1. **매거진은 표를 안 그린다.** `MAGAZINE_NODES` 11종에 `table`이 없다.
   그리고 `magazine-markdown.ts` 머리말이 못 박았다 — 안 그리는 노드가 섞이면
   **「저장은 되는데 화면엔 안 보이는」** 상태가 된다. 우리 브리프는 표가 뼈대라 **절반이 조용히 사라진다.**
2. **권한 모델이 정반대다.** 매거진 = 아무나 읽는 공개 글 + 편집자는 환경변수 이메일 몇 개(`magazine-auth.ts`).
   브리프 = **그 고객 한 분만** 읽는 사적 문서.

👉**결론 = 디자인은 빌리고 그릇은 따로 만든다.** 같은 테이블에 넣으면 서로 발목을 잡는다.

⭕**그런데 빌릴 게 하나 있다** — `markdownToDoc()`. 대표가 옵시디언 마크다운을 들고 오는 걸
전제로 만든 함수라 **노션에서 복사한 마크다운이 그대로 물린다.** 표 파싱만 얹으면 된다.

## 데이터 모델 (초안 — 대표 확인 필요)

```
brand_briefs
  id            bigint pk
  brand_id      bigint fk → brands(id)     -- 어느 소개서의 브리프인가
  owner_user_id bigint fk → users(id) null -- ⭐대표가 «수작업»으로 채운다. null이면 아무도 못 본다
  body          jsonb                      -- Tiptap 문서(매거진과 같은 형태 + table 노드)
  status        text                       -- draft | published
  published_at  timestamptz null
  created_at / updated_at
```

- 🔑**`owner_user_id`가 유일한 열쇠다.** null = 아직 연결 전 = **대표만** 본다.
- 🔗소개서 소유권(`brands.owner_user_id`)과 **따로 둔다.** 소개서는 「전달 대기」로 비워 두는 기간이 있고
  (런북 §전달 대기), 그 사이에도 브리프는 특정인에게 붙어 있어야 한다.
- ⚠️**소개서가 이관되어도 브리프는 자동으로 안 따라간다** — 대표가 수작업으로 맞춘다(대표 확정).
  🔗[[ownership-transfer-ripples]]의 「한 컬럼이 아니라 그 브랜드를 전제로 만든 모든 층」에 이게 한 층 더 는다.
  📌**런북에 브리프 칸을 추가해야 한다.**

## 화면

| 자리 | 무엇 |
|---|---|
| `/my` | 「요약 보고서」 카드 — `ReportArchiveCard` 패턴. 없으면 섹션 자체를 안 그린다 |
| `/brief/[id]` | 본문. **서버에서** `owner_user_id === 세션 사용자`를 확인. 아니면 404 |
| 편집 | 대표만. 마크다운 붙여넣기 → `markdownToDoc` → 미리보기 → 발행 |

🚨**권한은 서버에서 판정한다.** 매거진이 겪은 자리다 — `magazine-auth.ts` 주석:
*「클라이언트의 버튼 숨김은 UX일 뿐 보안이 아니다」*, `/magazine/new`에 주소를 직접 치고 들어오는 경로.

## 표 컴포넌트 스펙

```ts
// Tiptap 노드
table     -> tableRow[] 
tableRow  -> tableCell[]
tableCell -> { attrs: { header?: boolean; align?: 'left'|'right' }, content: paragraph[] }
```

- **머리글 행**: 첫 행만. 배경 한 톤, 12 mute, letter-spacing 약간
- **정렬**: 열 단위가 아니라 **셀 단위 `align`** — 숫자 표의 「숫자」 열만 오른쪽
- **숫자**: `font-variant-numeric: tabular-nums`(자릿수 맞춤)
- **넘침**: 표를 `overflow-x:auto` 컨테이너에 감싼다(19행·4열 대비)
- **빈 머리글 셀 허용** — 숫자 표의 번호 열이 빈칸이다(실측 6회)
- ⛔셀 병합·중첩 표는 **안 만든다.** 34개 중 0건이다

## 출시 단위 (작은 것부터)

1. **1단계** — `brand_briefs` 테이블 + `/brief/[id]` 읽기 화면 + 표 렌더러. 본문은 대표가 SQL로 넣는다
2. **2단계** — `/my` 「요약 보고서」 카드
3. **3단계** — 대표용 편집 화면(마크다운 붙여넣기 → 미리보기 → 발행)

⭐**1단계만으로도 오늘 나간 브리프 8건을 옮길 수 있다.** 2단계가 이 기능의 진짜 값이다.

## 미결 — 대표 확인 필요

1. **주소를 아는 사람은 보게 할까, 로그인한 주인만 볼까.** 위 표엔 「주인만」으로 적었는데(대표 확정),
   그러면 **소유권 연결 전에는 고객이 못 읽는다.** 지금은 링크만 있으면 읽는다.
   → 갈래 = ⓐ 주인만(연결될 때까지 대표가 노션으로 먼저 드린다) ⓑ 주인 + 링크 아는 사람
2. **노션을 계속 쓸까, 사이트 편집기로 옮겨갈까.** 3단계를 만들면 노션이 필요 없어진다.
   대표 퇴고가 노션에서 잘 돌아가고 있어서, **당분간 노션 유지**를 권한다.
3. 기존 브리프 8건을 **옮길까 두고 볼까** — 옮기면 표를 손으로 다시 만들어야 하는 건도 있다
