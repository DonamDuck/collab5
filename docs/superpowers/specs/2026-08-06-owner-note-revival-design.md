# 기획서: 사장님 특장점 한 문장 — `ownerNote` 되살리기 (백로그 B35)

- 날짜: 2026-08-06
- 상태: **검토 대기** (대표 리뷰 전)
- 발안: 대표 (지인 피드백 — 아그레아블의 특장점 *"걷고 뛰기 가능한 러닝크루"*)
- 배경 논의: 백로그 보드 B35 · 레드팀 3라운드(질문 게이트 2 + 설계 게이트 1)

## 1. 문제

AI 크롤은 웹에 있는 것만 캐온다. 그런데 브랜드의 진짜 특장점은 **사장님(또는 그 브랜드를 아는 사람) 머릿속에만** 있는
경우가 있다 — "걷고 뛰기 가능한 러닝크루"는 어떤 크롤도 못 만든다. 지금 이 문장을 넣는 통로는
"직접 추가 칩 + 별표"뿐인데 세 가지가 어긋난다:

1. **계약이 다르다** — 별표+직접 칩은 `verbatimKeywords`("그 표현 그대로 등장시켜라")로 전달된다.
   대표·지인의 진의는 **"단어가 그대로가 아니라, 이 설명과 맥락이 특장점으로 소개되면 된다"**(대표 원문 08-06).
2. **묻혀 있다** — 직접 추가 입력칸이 칩 화면 맨 아래에 있고 안내문이 `예: 수제, 비건`이라 짧은 단어를 유도한다.
   실사용 관찰(대표): 사장님들은 제안된 칩만 고르고 넘어간다.
3. **자리를 잡아먹는다** — 문장 하나가 칩 10칸·별표 6칸 중 하나를 소모한다.

## 2. 발견 — 서버는 이미 만들어져 있다 (이 기획의 성격을 바꾼 사실)

`OptionsInput.ownerNote`가 **이미 존재하고 서버 끝까지 배선돼 있다**:

- `src/lib/enrich.ts:80` — `ownerNote?: string; // 사장이 직접 쓴 한두 문장 — 생성의 최우선 중심축`
- `src/app/api/enrich/route.ts:206` — API가 이미 받는다
- `src/lib/enrich.ts:1786~` — 프롬프트 주입 블록도 이미 있다:
  *"⭐⭐가장 중요 — 사장이 직접 쓴 브랜드 핵심 설명이야. 이 내용·관점·강조점을 모든 후보의 최우선 중심으로 삼아줘(조사 자료보다 이걸 우선)"*

역사: 옛 인테이크(인터뷰 4스텝, `9dfa3dd`)에 입력칸이 있었는데 **위저드 v3 개편(`f9789c9`)에서 UI만 사라지고
서버 배선이 남았다.** 기존 프롬프트 계약("내용·관점·강조점" = 의미 기반)이 대표 진의와 정확히 일치한다.

→ **이 기획은 신설이 아니라 되살리기 + 다듬기다.** 새 필드를 만들지 않는다(`ownerNote` 재사용).

## 3. 결정 사항 (대표 확정 08-06)

| 질문 | 결정 |
|---|---|
| 누가 쓰는 칸인가 | **대표(운영자)가 위저드 돌릴 때** 가 1차 사용자. 단 사장님 셀프서브에도 그대로 노출(추가 비용 0) |
| 어디에 두나 | **크롤 결과(칩 선택) 화면 최상단** — 대표 제안. 맨 아래 묻힌 지금 구조가 원인이므로 |
| 계약 | **의미·맥락이 특장점으로 드러나면 됨. 표현은 자유.** 단어 그대로 박기 아님(verbatim과 구분) |
| 반영 대상 | 자세히 소개·활동. **한 줄 소개는 대상에서 제외**(20~40자 제약·슬로건 규칙과 충돌 — 레드팀 게이트에서 조건부 허용 문구를 삭제하고 단순 금지로 통일) |
| 입력 개수 | **1문장** (제약이 곧 정체성 — "꼭 넣고 싶은 그 한마디") |

## 4. 설계

### 4-1. UI (`EnrichWizard.tsx`, 칩 스텝 상단)

- 칩 그리드 **위**에 텍스트 입력 1개. 항상 보임(접기 없음).
  - 라벨: **"사장님만 아는 특장점이 있다면 한 문장으로 알려주세요 (선택)"**
  - placeholder: `예: 걷고 뛰기 모두 가능한 러닝크루예요`
  - `maxLength=100`, 1줄 input(개행 불가)
- **칩으로 만들지 않는다.** 입력칸 자체가 표시 장소다(값이 남아 있으면 그게 곧 확인 상태, 지우면 삭제).
  칩 10칸·별표 6칸을 소모하지 않는다. — 레드팀 판정: "문장을 칩 모양에 넣으면 깨져 보인다. 어휘를 섞지 마라."
- 상태는 `ownerNote` state로 보관, `generate()` 요청 body에 `ownerNote` 필드로 전송(빈 문자열이면 생략).

### 4-2. 프롬프트 다듬기 (`enrich.ts` ownerNote 블록 — 기존 블록을 교체)

기존: "모든 후보의 최우선 중심으로 삼아줘"(과함 — 한 줄 소개까지 밀어넣게 읽힘).
교체안(요지):

> ⭐⭐사장이 직접 쓴 특장점 한 문장이다(조사 자료보다 우선하는 1순위 사실).
> ①이 **의미와 맥락**이 자세히 소개(descriptions)와 활동(activityHints) 중 가장 어울리는 곳에 **반드시 드러나게** 하라.
>   표현은 자연스럽게 다듬어도 되지만 **사실을 왜곡하거나 약화하지 마라**.
> ②한 줄 소개에는 넣지 마라(자세히·활동이 이 문장의 자리다).
> ⑤자랑을 여러 개 나열한 입력이면 **가장 구체적인 사실 하나만** 채택해 살려라.
> ③특장점 안의 **검증 불가한 수치·수상·최상급**("10년 무사고", "지역 1위")은 단정하지 말고 완화 표현으로.
> ④특장점이 상투어("정성을 다합니다")면 **내용은 살리되 표현은 지침의 문체 규칙이 이긴다**.

- ③ = 사실 게이트 우회 방지(레드팀). ④ = 상투어 블랙리스트와의 우선순위 명시(충돌 예방 — 08-02 3연발 교훈).
- 반영 전 **반대 방향 문장 grep** 필수: `최우선`·`신뢰 순서`·`상투어`·`슬로건 앵글` 주변.
- ✅**유령 호출자 확인 완료(08-06 grep)** — `ownerNote`를 보내는 코드는 현재 **0곳**(타입·API 수신부·프롬프트 블록만 존재).
  옛 인테이크 UI는 위저드 v3에서 삭제됨 → 블록 계약을 바꿔도 기존 동작 변화 없음.

### 4-3. 서버 사후 확인 — ⚠️보장이 아니라 **표본 추출 신호**다 (레드팀 재정의)

프롬프트는 요청이고 보장은 파서가 한다(상시 규칙). 그런데 이 계약은 **의미 기반**이라 표면 단어 검사로는
보장할 수 없다 — "걷고 뛰기"가 "달리기 실력과 무관하게"로 잘 표현될수록 겹침이 0이 된다(오탐).
따라서 이 확인은 **품질 게이트가 아니라 사람이 들여다볼 표본을 고르는 신호**로 설계한다:

- options 파싱 직후, `ownerNote`의 내용어(2글자 이상 조각)와 `descriptions + activityHints(title·desc)`의 겹침 검사.
- 겹침 0이면 `console.warn("[owner-note-check]", { note, 자세히·활동 발췌 })` — **원문과 발췌를 같이 남겨**
  사람이 로그 한 줄만 보고 "누락인가, 좋은 의역인가"를 판정할 수 있게. 재시도 없음(콜 상한 불변).
- ⛔**사용자 화면 어디에도 "반드시 반영됩니다"라고 쓰지 않는다** — 그 보장은 존재하지 않는다.
- 순수 함수로 분리해 단위 테스트(`scripts/test-enrich-guards.ts`에 케이스 추가).

### 4-4. 저장·다시 받기

- `buildEnrichment()`(`src/lib/enrichment.ts`)에 `ownerNote?: string` 추가 → 소개서의 크롤 스냅샷에 함께 저장.
- **"초안 다시 받기"**(`page.tsx` redraft)가 스냅샷의 `ownerNote`를 요청에 포함 — 다시 받아도 특장점이 유지된다.
- ⭐**보이지 않는 재주입 금지**(레드팀 CONFIRMED) — 저장된 특장점이 있으면 "다시 받기" 버튼 옆에
  **읽기 전용으로 표시 + [지우기]** 한 줄을 둔다. 안 보이는 문장이 매번 다시 들어가면, 잘못 쓴 특장점이
  "왜 자꾸 이상하게 나오지"의 보이지 않는 원인이 되고 위저드를 다시 돌리는 것 말곤 출구가 없다.
  (수정 UI는 스코프 밖 유지 — 지우고 새로 받는 것으로 충분)
- `Enrichment` 타입(`types.ts`)에 필드 추가. DB는 jsonb라 마이그레이션 불필요.

### 4-5. 비용

- 위저드 콜 수 불변(0콜 추가). 배포 후 실검 1콜(~100원, 대표 승인 후): 아그레아블 잔여 파일럿 또는
  임의 업체에 ownerNote를 넣고 생성 → 특장점이 자세히·활동에 어떻게 드러나는지 확인.

## 5. 하지 않는 것 (스코프 밖)

- 여러 문장 입력·칸(섹션) 지정 UI — C안, 기각(YAGNI)
- 셀프서브 사장님용 문구 실험·온보딩 최적화 — 셀프서브 볼륨이 생기면
- `verbatimKeywords` 경로 변경 — 기존 별표 칩 동작은 그대로(계약 분리 유지)
- 기존 소개서 소급 — 새로 생성/다시 받기부터 적용

## 6. 엣지 케이스

| 상황 | 동작 |
|---|---|
| 빈 입력 | 필드 생략 — 기존과 완전 동일 |
| 100자 초과 | maxLength로 입력 자체 차단 |
| 특장점이 크롤 사실과 모순 | 사장 발화가 이긴다(기존 신뢰 서열 "사장님 글 최우선"과 일치). 검증 불가 수치만 완화 |
| 특장점이 이미 크롤에 있는 내용 | 무해 — 강조가 겹칠 뿐 |
| "다시 받기" 반복 | 스냅샷에서 매번 재전달 — 유지됨 |
| 회귀 | 기존 회귀 테스트(ownerNote 없는 입력)는 영향 없음 — 필드 생략 시 프롬프트 불변 |

## 7. 완료 조건

1. 위저드 칩 화면 상단에 입력칸 노출, 입력 시 생성 요청에 포함
2. 프롬프트 블록 교체(안전장치 ③④⑤ 포함) + 반대 방향 grep 기록
3. 사후 확인 로그(원문+발췌 동봉) + 단위 테스트 통과 (`tsc`·`build`·기존 회귀 포함)
4. 스냅샷 저장·다시 받기 유지 + **저장된 특장점 표시·[지우기]** 동작 확인
5. 실검 1콜에서 특장점이 자세히 또는 활동에 의미로 드러남 (대표 확인)
