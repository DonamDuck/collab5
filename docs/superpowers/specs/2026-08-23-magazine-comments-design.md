# 매거진 댓글 — 설계

날짜: 2026-08-23
요청: 대표 (2026-08-23)
관련: `ArticleLikeBar.tsx`(계약 원본) · `collab_requests`(대안으로 검토됨) · [[브랜드-보이스]]

## 한 줄

매거진 아티클에 **댓글**을 단다. 표시 이름은 **브랜드명**이고 **그 브랜드 소개서로 링크**된다.

## 왜 이 모양인가 — 대표 확정 사항

| 결정 | 값 | 근거 |
|---|---|---|
| 목표 | **콜라보 접점** | 6개월 뒤 늘어 있을 것으로 대표가 고름 |
| 표시 이름 | **브랜드명**(마스킹 없음) | 아래 §마스킹이 폐기된 이유 |
| 이름 필드 신설 | **안 한다** | 아래 §본인인증 |
| 로그인 | **쓰기만 필수, 읽기는 공개** | 좋아요 바와 같은 계약 |
| 숫자 표시 | **댓글 수·좋아요 수 모두 숨김** | 08-15 좋아요 수 숨김 결정과 일관. 데이터는 쌓인다 |
| 버튼 문구 | **「댓글 남기기」** | 「등록」보다 우리 말투(잘 읽었어요·콜라보 찾기)에 붙는다 |
| 삭제 | **본인 것만** | 잘못 쓴 걸 못 지우는 게 더 큰 문제 |

### 마스킹이 폐기된 이유
대표 최초 요청은 *「이름은 성만 표시하고 나머지는 마스킹」*이었다. 그런데 **개인 이름 필드가 없다** —
`users`는 `user_id, uuid, brand_name, phone, email, profile_image`가 전부고 가입 폼은 **브랜드명**(예: 캔버스가든)을 받는다.
「캔버스가든」을 마스킹하면 「캔**」이 되어 뜻이 사라진다.
⭐그리고 **마스킹은 네이버 뉴스의 장치**다 — 익명 대중 + 악플 방어가 전제. 우리 독자는 서로 아는 브랜드 운영자라 전제가 다르다.
브런치(필명 노출)·인스타(핸들 노출) 쪽이 우리 모양이다.

### 본인인증 — 이름 필드를 지금 안 받는 이유
*「나중에 본인인증 할 테니 이름을 먼저 받자」*가 검토됐고 **폐기**됐다.
🚨**PASS·휴대폰 인증은 실명을 «돌려준다».** 미리 받아 대조하는 방식이 아니다 — 의존 방향이 거꾸로였다.
덧붙여 목적을 「본인인증」으로 적고 화면에 표시하면 **목적 외 이용**이 된다.
→ 인증을 붙일 때 그때 받는다. 댓글은 브랜드명으로 간다.

### ⭐ 우리만 할 수 있는 것
> **댓글에 뜬 브랜드명을 누르면 그 브랜드 소개서(`/m/{slug}`)로 간다.**

네이버·브런치·인스타 어디에도 없다(그들에겐 브랜드 페이지가 없다).
레드팀 표현 — *「문제는 문자열이 아니라 링크다. 링크 없는 이름은 장식이고, 링크 걸린 이름은 콜라보 개시점이다.」*

## 화면

아티클 본문 맨 아래.

```
─────────────────────────────
댓글                              ← 개수 없음(숨김)
─────────────────────────────
[로고] 캔버스가든  ·  2일 전        ← 이름·로고 누르면 /m/{slug}
       잘 봤어요. 저희도 해보고 싶었어요.        [삭제]  ← 본인 것만
─────────────────────────────
[ 댓글을 남겨보세요…              ]
                    [ 댓글 남기기 ]
```

- **비로그인**: 입력칸 자리에 「로그인하고 댓글 남기기」 버튼. 누르면 좋아요 바와 **같은 얼럿**.
- **빈 상태**: 「첫 댓글을 남겨보세요」 한 줄.
  🚨⭐**개수를 숨겨도 「0」은 안 숨겨진다 — 렌더된 목록이 곧 개수다.**
  대표는 「댓글 수 표시」를 뺐지만, 글이 1편이고 회원이 11명인 지금 **이 빈 화면이 영구 기본값**이다.
  숫자를 숨긴 것이 이 노출을 막아주지 않는다는 걸 분명히 해 둔다(레드팀 CONFIRMED).
- 정렬 **오래된 순**(대화 흐름). 토글 없음. 📌대표 지시가 아니라 **내가 정한 것** — 뒤집기 쉬움.
- 로고 = 기존 `Avatar` 컴포넌트 + `profile_image`. 없으면 이니셜.

## 플로팅 바

지금 「잘 읽었어요 ❤️」 알약 옆에 **댓글 알약**을 붙인다.

1. 누르면 댓글 섹션으로 스무스 스크롤.
2. **댓글 섹션이 뷰포트에 들어오면 댓글 알약이 사라지고** 좋아요만 남는다(중복 제거).
3. 위로 올리면 되돌아온다.

- `IntersectionObserver` — `Reveal.tsx`가 이미 라이브러리 없이 쓰는 패턴. 새로 들일 것 없다.
- `prefers-reduced-motion`이면 애니 없이 즉시 전환.
- 🚨`pointer-events-none`을 띠에 유지한다 — 알약이 둘이 되면 빈 곳이 더 넓어져 본문 클릭을 삼킨다(이미 두 번 밟은 함정).
- 📏**실측(2026-08-23)**: 「잘 읽었어요 ❤️」 알약 **138×51px** · 루트 폰트 **17px** · `main`의 `pb-28` = **119px** · `max-w-[680px]`.
  → 댓글 알약을 더해도 **최악 138+8+138 = 284px**로, 375px 화면의 가용폭 343px(px-4 좌우 32px 제외) 안에 들어간다. **안무 성립.**
- ⚠️`pb-28`(119px)은 **본문용**이다. 댓글 섹션이 본문 아래 붙으므로 **댓글 섹션 하단에도 같은 119px**을 준다 —
  안 주면 플로팅 알약이 「댓글 남기기」 버튼을 덮는다.

## 데이터

`magazine_comments` — `magazine_likes`와 같은 모양.

| 컬럼 | 타입 | |
|---|---|---|
| `id` | bigint PK | |
| `article_id` | bigint | FK `magazine_articles` |
| `user_id` | bigint | FK `users` — 삭제 권한 판정용 |
| `author_name` | text | ⭐**쓸 때의 브랜드명 스냅샷** |
| `author_slug` | text null | ⭐**쓸 때의 소개서 slug 스냅샷**(없을 수 있음) |
| `body` | text | **500자 상한**(서버에서도 검증) |
| `created_at` | timestamptz | ⚠️타입 유지(KST 표기는 `lib/time.ts`) |
| `deleted_at` | timestamptz null | **soft delete** — 행은 남긴다 |

인덱스: `(article_id, created_at)`.

### 🚨 왜 조인이 아니라 스냅샷인가 (레드팀 CONFIRMED)
`user_id`만 저장하고 읽을 때 조인하면 두 가지가 조용히 망가진다.
1. **브랜드명을 바꾸면 과거 댓글의 작성자가 전부 소급해서 바뀐다.** 3개월 전 대화의 화자가 달라진다.
2. **소유권을 이전하면** 그 사람이 브랜드를 잃고, 링크가 사라지거나 남의 페이지를 가리킨다.
   (소유권 이전 파장으로 08-06·08-07 두 번 터진 이력이 있다 → [[ownership-transfer-ripples]])

⭐**우리 코드에 이미 답이 있다.** `MagazineBrandLink`가 같은 이유로 FK가 아니라 **slug·name 스냅샷**을 쓴다
— *「소개서가 삭제·개명돼도 발행된 기록은 남아야 한다」*(`types.ts:321`). **댓글도 같은 규칙을 따른다. 새 규칙을 만들지 않는다.**

### 🔗 링크할 소개서를 어떻게 고르나
`users.brand_name`(계정 이름)과 `brands.slug`(소개서)는 **자동으로 이어져 있지 않다.**
한 계정이 소개서를 여러 개 가질 수 있다(대표 계정은 14개).

**1차 규칙 — 단순하게:**
- 그 계정의 소개서가 **정확히 1개**면 → `author_slug`에 그 slug를 넣고 **이름이 링크가 된다**
- **0개거나 2개 이상**이면 → `author_slug`는 `null`, **이름만 평범한 텍스트로** 뜬다.
  ⛔**링크처럼 보이는데 안 눌리게 만들지 않는다** — 죽은 링크는 「눌러도 아무 일 없음」보다 답답하다.
  밑줄·색·커서 전부 없이 그냥 글자다(대표 확정 08-23: *「소개서 없는 경우엔 일단 아무 반응 없게」*).
  ⏭이 자리의 동작 정의는 **백로그**로.

⏭「어느 소개서로 남길지 고르기」는 **YAGNI로 미룬다.** /m 소개서의 제안 시트에 `viewerBrands` 칩 선택이라는
**같은 패턴이 이미 있어서**(page.tsx:167) 나중에 붙이기 쉽다. 지금 회원 11명 중 소개서 2개 이상인 건 대표뿐이다.
🚨**표를 만들기 전엔 서버 액션이 에러를 반환해야 한다** — 좋아요와 같은 규칙(조용히 성공한 척 금지).

## 입력 안전 — 자기검토에서 빠져 있던 것

- **XSS**: `body`는 **순수 텍스트**로만 렌더한다(React 기본 이스케이프). ⛔`dangerouslySetInnerHTML` 금지.
  매거진 본문은 리치텍스트(JSON)지만 **댓글은 리치텍스트가 아니다** — 링크 자동변환도 하지 않는다(1차 범위 밖).
- **개행**: 저장은 그대로, 렌더는 `whitespace-pre-wrap`. ⚠️연속 개행은 **최대 2줄로 접어** 저장(도배 방지).
- **길이**: 클라 `maxLength=500` + **서버에서 다시 검증**(클라 우회 차단). 공백만 있는 글은 거절.
- **도배**: 같은 사용자가 **같은 글에 10초 내 연속 등록** 시 서버가 거절. 낙관적 반영이라 클라만으론 못 막는다.
- **삭제된 댓글**: 행은 남기되 **화면에서는 완전히 없앤다**(「삭제된 댓글입니다」 자리표시 안 함).
  회원 11명 규모에서 빈 자리표시는 「누가 뭘 지웠나」를 오히려 도드라지게 한다.
- **시각 표기**: 「2일 전」 상대 시간. 7일이 넘으면 「8월 15일」 절대 날짜. KST(`lib/time.ts`).

## 모더레이션 (레드팀 CONFIRMED)

댓글은 **공개 쓰기 표면**이다. 본인 삭제만 있으면 팀은 아무것도 못 지운다.

- **본인 삭제** — 화면에 [삭제]. 서버가 `user_id` 일치를 확인한다.
- **운영자 삭제** — `adminDeleteArticleComment(commentId)`. ⛔**화면은 만들지 않는다**(YAGNI).
  🚨**당분간 지우는 방법은 대표가 SQL을 돌리는 것뿐이다** — 이 사실을 구현자가 «발견»하게 두지 않는다.
  ```sql
  UPDATE magazine_comments SET deleted_at = now() WHERE id = <id>;
  ```
- 신고 기능 없음. 회원 11명 규모에서 신고는 대표에게 카톡 한 통이 더 빠르다.

## 재사용 — 새 규칙을 만들지 않는다

`ArticleLikeBar`의 계약을 **그대로** 쓴다.
- 로그인 유도 얼럿(`useDismissable`, 딤 클릭으로 안 닫힘, [취소][로그인] + 회원가입 줄)
- `sessionStorage` 의도 저장 → 복귀 후 자동 재개.
  ⭐**댓글은 「쓰던 글」까지 담는다** — 로그인하고 돌아왔는데 쓰던 문장이 사라지면 두 번 쓰게 된다.
  ⚠️**단 좋아요와 달리 «자동 등록하지 않는다». 복원까지만 하고 등록은 본인이 누른다.**
  좋아요는 되돌릴 수 있고 사적이지만 **댓글은 되돌릴 수 없는 공개 발언**이다. 같은 훅을 쓰되 이 한 걸음은 다르다
  — 이 차이를 적어 두지 않으면 다음 사람이 「좋아요와 다르네」 하고 «고쳐» 버린다(레드팀 NIT).
- 낙관적 반영 + 실패 시 롤백
- `print:hidden`

## 안 만드는 것 (YAGNI)
