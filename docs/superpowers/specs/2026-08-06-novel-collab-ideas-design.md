# 기발한 콜라보 아이디어 섹션 (B36) — 설계

> 2026-08-06 · 2팀 · 대표 확정 설계
> 발단 = 지인 피드백 *"러닝크루×러닝크루, 러닝크루×카페를 하면 대부분 **예상되는 콜라보**를 하게 된다"*
> 근거 = 같은 날 실험 3판(v1 A/B → v2 → v3, Gemini 29콜 ≈ 340원). 결론은 전부 대표 판정으로 확정됨.

---

## 왜 만드나

지금 리포트의 `ideas` 2~3개는 **각자의 경험·활동에서 출발**한다. 안전하지만 그래서 **예상 범위 안**이다.
기존 섹션은 그대로 두고, **해왔던 것에 얽매이지 않는 기발한 제안**을 별도 섹션으로 붙인다.

⚠️ 이 기능의 진짜 위험은 "안 나오는 것"이 아니라 **뜬구름이 나오는 것**이다. 실험 전제도 그거였고
(*"기발한 게 실제로 나오긴 하나"*), 결과는 **나온다 + 단 게이트 없이는 절반이 헛말이 된다**였다.

---

## 확정 설계 — 5단계

```
① 생성  → ② 게이트 → ③ 4축 채점 → ④ 겹침 제거 → ⑤ 2개 노출
```

### ① 생성 — 기발함 기준 4개를 프롬프트에 (A/B로 검증됨)

| 기준 | 내용 |
|---|---|
| **양방향 교환 불가** | A를 같은 업종 아무 가게로 바꿔도 성립하면 실격. **B를 바꿔도** 마찬가지. 둘 다 대체 불가여야 한다 |
| **예상 회피** | 이 업종 조합에서 누구나 떠올릴 아이디어 3개를 먼저 나열하고, 겹치면 버린다 |
| **SNS 확산** | 게시물로 올라갔을 때 "누가 봐도 공익적" 또는 "누가 봐도 재밌다". 눈살 찌푸릴 여지가 있으면 안 된다 |
| **상대 서비스 침투** | 결과물이 상대의 앱·프로그램·활동 **안에서** 쓰이거나 등장하면 가점 |

- ⭐**입력에 Brand DNA(특히 `signature`)를 반드시 넣는다.** v2에서 이걸 빼먹었더니 희소성이 통째로 죽었다.
- **후보 16개**(관점 2개 × 8). 관점 = ⓐ만드는 물건에서 출발 ⓑ상대의 기존 활동·서비스에서 출발.
  8개로 줄이면 최고점이 내려간다(실측 35 → 33).
- ⛔**"서로 다른 각도여야 한다"는 다양성 압박을 생성 단계에 넣지 마라.** 최고점 아이디어를 밀어낸다(v2 실패).
  다양성은 ⑤에서 선발로 확보한다.

### ② 게이트 — 하나라도 걸리면 탈락 (점수를 보지 않는다)

- **실행**: 이미 가진 것으로 한 달 안에 첫 회를 열 수 있나. 평소 규모를 넘는 대관·장비·예산·**해외 출장**이면 탈락
- **사실**: 소개서·DNA에 없는 재료·설비·프로그램을 지어냈으면 탈락
- **구체성**: 무엇을 어디서 하고 참가자가 뭘 하고 가는지가 그려지나
- **양쪽 이득**: 한쪽만 좋으면 탈락(그건 협찬이지 콜라보가 아니다)

> 🚨 **게이트는 선택이 아니다.** 캔버스가든×로컬페이지(성북구 ↔ 필리핀)에서 **16개 중 8개가 탈락**했다.
> 전부 *"성북 공방이 현지에서"*였다. **지역이 먼 쌍일수록 기발함을 요구하면 실행 불가로 튄다.**

### ③ 4축 채점 (게이트 통과분만, 각 0~10)

| 축 | 내용 |
|---|---|
| `exchange` | 양방향 교환 불가성 |
| `unexpected` | 예상 목록과의 거리 |
| `light` | 첫 회를 여는 준비의 양. 기존 정기 모임·벙개 형식을 그대로 쓰면 만점 |
| `viral` | **게시물로서의 매력**(⚠️정의 주의 — "결과물이 물리적으로 돌아다니나"가 아니다) |

- `viral`에 **눈살 리스크 감점**을 포함한다(무속 조롱·신체 조롱·특정 집단 대상화).
  단 **부적·액막이 소재 자체는 감점 사유가 아니다** — 놀이·재치로 읽히면 오히려 가점.
- ⭐`light`와 `viral`은 **대표의 판단 문장에서 역추출한 축**이다. 넣었더니 대표가 손으로 고른 1위가
  숫자로 그대로 재현됐다(액막이 오마모리 35점 1위 / 촉각 지도는 난이도 때문에 3위).

### ④ 겹침 제거 — **행위 기준으로, 좁게**

기존 `ideas`를 입력으로 주고 판정시킨다. **제목이 아니라 핵심 행위**로 본다.

- ✅겹침: 계기·활동·결과물이 사실상 같아서 **나란히 보면 "같은 말 아닌가?"** 할 때
- ⛔겹침 아님: 결과물 종류만 같음(둘 다 키링) / 재료만 같음(둘 다 헌 옷 — 이 공방의 본업이라 당연) /
  같은 브랜드의 **다른 프로그램**에 붙음(북클럽에 붙는 것과 러닝에 붙는 것은 다르다)

> v2는 "둘 다 키링"이면 겹쳤다고 오판했다. v3에서 좁히자 4건 전부 정확해졌다.
> 🚨 **겹침 제거는 필수다** — DNA를 넣으면 **기존 프롬프트가 이미 최고 아이디어를 찾아낸다.**
> 실제로 어제 기발 1위였던 오마모리가 오늘은 **기존 1번으로 올라왔다.** 안 거르면 기발 섹션이 위를 따라 한다.

### ⑤ 노출 — 2개 고정 (대표 확정)

- 기존 `ideas` 2~3개를 **먼저** 보여주고, 그 아래 기발 섹션 **2개**.
- 2개는 **계열(family)이 서로 달라야** 한다. family는 **만드는 결과물**로 분류한다:
  `부적 / 액자 / 인형 / 가방·파우치 / 의류·착용품 / 현판·표식 / 뜨개물 / 지도·기록물 / 음식·음료 / 콘텐츠·영상 / 기타`
  ⛔`워크숍`·`벙개`·`팝업`·`클래스`는 **형식이지 결과물이 아니다** — family로 쓰면 전부 한 덩어리가 된다(v2 실패).
- 2개는 **모티프(핵심 장치)도 서로 달라야** 한다. family와 **별도 필드**로 뽑는다
  (심사관이 「오마모리 주머니」를 '가방·파우치'로 분류했듯 family가 모티프를 못 잡는다).
- ⭐**모티프는 탈락 사유가 아니다**(대표 판정). **기존↔기발 사이는 모티프가 겹쳐도 된다** — 행위만 다르면.
  같은 모티프가 일반 아이디어로도, 기발로도 각각 유효할 수 있다(실제로 기존 1번과 기발 1위가 그 사례).
  제약은 **기발 2개 내부에만** 건다(나란히 붙는 두 줄이 둘 다 부적이면 "또 부적?").

## 실험 근거 요약

| 판정 | 근거 |
|---|---|
| 기발함 기준을 넣는다(A/B의 B) | 상위 6개 중 5개가 B. **뻔한 아이디어는 전부 A에서만** 나왔다 = 기준의 효과는 천장이 아니라 **바닥** |
| 채점기를 믿어도 된다 | 뻔한 미끼 4개를 심어 블라인드 채점 → **전부 최하위** |
| 생성과 심사를 분리한다 | 한 프롬프트가 내고 스스로 고르면 자기 편을 든다 |
| 후보 16개 | 8개로 줄이면 최고점 35→33 |
| `gain_a`/`gain_b` 강제 | 강제했더니 **한쪽만 좋은 아이디어가 아예 안 나왔다** |

### ⭐부수 발견 — 기존 `ideas`에도 mutuality가 필요하다
`REPORT_SYSTEM`은 `candidates` 채점에만 `mutuality`가 있고 **`ideas`에는 없다**.
접점은 양쪽을 보고 고르는데 정작 아이디어는 그 검사 없이 나간다. B36 착수 시 같이 이식한다.

### 🎲 좋은 한 방은 후보 풀 크기의 함수다
어제 1위(「계단 턱 액막이 오마모리+앱 인증」)는 오늘 16개에 안 들어왔다. 대신 같은 뿌리의
「헌 옷 자투리 **계단 측정 줄자**」(센티미터 대신 **접근 레벨별 색상 단추**)가 1위로 나왔다.
→ **매번 다르다**는 게 이 기능의 성질이다. "다시 받기"가 여기서 특히 값지다.

## 구현 시 결정할 것 (실측 후)

⏱ **시간·비용이 이 기능의 유일한 리스크다.** 현재 리포트 = **1콜 25초 35원**(07-26에 48초 85원에서 내린 값).
실험 구성을 그대로 옮기면 **+3콜**이 된다.

| 안 | 콜 | 예상 시간 | 비고 |
|---|---|---|---|
| A. 실험 그대로 | +3 (생성2·심사1) | +30초 | 품질 최고, 검증된 구성 |
| B. 생성 1콜로 16개 | +2 | +20초 | 관점 2개를 한 프롬프트에. 다양성 확인 필요 |
| C. lazy 생성 | +0 (초기) | 0 | 리포트 먼저 보여주고 기발은 나중에 붙임. DNA의 lazy 패턴 재사용 |

- **생성 콜은 기존 리포트 콜과 병렬로** 시작할 수 있다(입력이 같다). 심사만 리포트 결과를 기다린다.
  → 총 시간 = `max(리포트, 기발생성) + 심사`.
- 착수 순서: **A로 구현 → 실측 → 40초를 넘으면 B·C 검토.**
