# collab-page-enrich — 기존 소개서 보강

이미 발행된 `/m/{slug}` 소개서를 대상으로, `/collab-ab-test`의 B가 하던 리서치 보강을
단독 워크플로로 수행한다. **신규 생성 아님**(그건 `/collab-brandpage-creation-basic`(정식 제작은 `/collab-brandpage-creation-with-insta`)),
**실험 아님**(그건 `/collab-ab-test`). 핵심 차이는 **보고 게이트**:

```
① 현재 상태 진단 → ② 리서치(웹 + 🆕인스타 전량 수확) → ③ 후보·보강안 보고 ⛔대표 OK 대기⛔
        → ④ 수정 + 사진 폴더 회수 → ⑤ 재검증 보고 → 🆕⑥ 퇴고 역분석(대표 수정 → 프롬프트)
```

⭐**대표를 한 스텝씩 이끈다**(대표 지시 08-02). 각 단계 끝에서 **다음에 무엇을 할지와 지금 필요한 것**을
한 줄로 말하고 넘어간다 — 특히 ②는 시작 전에 *"어느 탭에 로그인돼 있나요"*, ③은 *"몇 번을 고르시겠어요"*를
명시적으로 묻는다. 대표가 "지금 뭘 하면 되지?"를 되묻게 만들지 마라.

| 단계 | 대표가 하는 일 | 내가 내놓는 것 |
|---|---|---|
| ① | — | 섹션별 진단표 |
| ② | 인스타 로그인 탭 열어주기 | 수확 건수·차단 여부 보고 |
| ③-A | **후보 선택**(활동·콜라보 각 30까지 — 🔎근거 = `src/lib/limits.ts`) | 후보 페이지(캡션 전문 포함) |
| ③-B | **문안을 페이지에서 직접 수정** → [전체 복사] 1회 | 검토판(편집 가능·복사 3단 폴백) |
| ④ | 사진 드래그(자동 불가 — §④-B) | 문안 반영 + 사진 폴더 |
| ⑤ | — | 반영 결과 + 미결 목록 |
| ⑥ | 프롬프트 반영 여부 판단 | 대표 수정 역분석 → 규칙 후보 |

⚠️ **③에서 멈추는 게 이 스킬의 정체성이다.** 리서치가 아무리 좋아도
대표 OK 없이 prod 페이지를 고치지 않는다. "보강해줘"라는 요청 자체는
①~③까지의 승인이지 ④의 승인이 아니다.

⭐ **보강은 제품 파이프라인의 대체가 아니라 같은 규칙의 수동 실행이다.** 아래 콘텐츠 정책은
`src/lib/enrich.ts`의 `BRAND_VOICE`·`OPTIONS_SYSTEM`·조사 프롬프트와 **같은 정본**을 따른다
(정본 = Obsidian [[크롤-키워드-재설계]] · [[브랜드-보이스]] · memory `enrich-model-config`).
사람이 손으로 넣는다고 규칙이 느슨해지지 않는다 — 오히려 서버 게이트를 안 거치니 더 엄해야 한다.

## ① 현재 상태 진단

`/m/{slug}`를 읽고 섹션별 현황을 표로 만든다:

| 섹션 | 현재 내용 요약 | 상태 판정 |
|---|---|---|
| 한줄 소개 / 자세히 / 시작 이야기 | | 좋음·평이함·빈약 + ⭐어투 규칙 위반 유무 |
| 대표 활동 (0~30) | | 개수 + 구체성(고유명사 유무) + ⭐**활동/콜라보 오분류** |
| 함께한 콜라보 | | ⭐아래 '콜라보 정합성' 체크 |
| 제공 콜라보 / 찾는 파트너 | | ⭐거절 문구가 섞여 있지 않은지 |
| 신뢰 정보 (주소·홈피·인스타·지도) | | ⭐**핸들·URL 실물 대조** |
| 키워드 칩 / 블록 6종 | | press 링크 실물 대조 |

- **신뢰 정보는 실제로 열어 확인한다.** 크롤이 넣은 인스타 핸들이 오타·유사계정인 경우가
  실재한다 (로컬페이지: 페이지엔 `@lokalpagestour`, 실제는 `@lokalpage_tour`).
- ⭐**활동 vs 콜라보 판별**(대표 지시 07-27, 조사·생성 프롬프트 양쪽에 들어간 규칙):
  **"누구와 함께"가 붙어야 성립하면 콜라보다.** 그 상대가 없어도 늘 하는 일이어야 활동이다.
  협업·공동제작·입점(백화점·편집숍·마켓)·팝업 참여·페어 참가·외부 기관 수업이 `activities`에 있으면
  `collabHistory`로 옮기는 제안을 올린다.
- **콜라보 정합성**: "함께한 콜라보"에 **입점·판매 채널**(마이리얼트립·인터파크·쿠팡 등
  플랫폼 유통)이 들어있으면 제거 후보로 올린다. 우리가 지향하는 콜라보는
  공동 기획·팝업·콘텐츠 같은 **파트너십**이지 판매 채널 등록이 아니다
  (2026-07-22 대표 확정, 로컬페이지 케이스).
- ⭐**주체 확인** — 제3자가 이 브랜드를 *소재로* 만든 것(남이 쓴 책·소설, 기사, 방송, 남의 리뷰)은
  이 브랜드의 활동도 제품도 아니다. `press` 블록으로 간다.
- ⭐**협업 산출물을 상시 제품처럼 쓰지 않기** — 팝업 협업으로 낸 향수를 "향수까지 갖추고 있어요"로
  쓰면 틀린 문장이다. "○○와 함께 향수를 선보였어요"로 맥락을 살린다.
- 🆕**소개서 섹션 순서가 08-12에 바뀌었다** — 「이런 콜라보를 찾고 있어요」(문장+유형 칩)가 **자세히 소개 바로 뒤 두 번째 칸**,
  「이런 콜라보를 제공할 수 있어요」는 **함께한 콜라보 뒤**. 위는 문(누가 노크할 수 있나) 아래는 제안(뭘 줄 수 있나)이라 떼어 놓았다.
  ⭐보강 문안을 쓸 때 **「찾고 있어요」엔 조건(형태·규모)을 담을 수 있는지** 보라 — 사장님이 조건을 걸고 싶어도
  우리가 「파트너」라고만 물어서 *누구*만 적혀 있는 소개서가 많다(계단뿌셔클럽 사례).
- ⭐**거절 목록 방어** — "유료 홍보·체험단 문의는 받지 않습니다"가 `seeksDescription`에 있으면 정반대 뜻이 된다.
  "A를 제외한 협업엔 열려 있어요" 식으로 감싸는 것도 금지 — 통째로 뺀다.
- ⭐**[고객]은 사람 집단만** — 임산부·초보자·지역 주민·직장인은 고객, 마음공부·불안·유연성·힐링은 고객이 아니라 주제다.
  판별: 뒤에 "~하는 분들"을 붙여야 말이 되면 그건 `targetAudience`가 아니라 `description` 재료다.

### ⭐press 블록 실물 대조 (07-29 prod 전수 감사에서 확립)

prod press 15항목을 전수 대조한 결과 **창작은 0건**이었지만, 대조 방법에서 함정 3개가 나왔다:

1. ⚠️ **브랜드명만으로 기사를 대조하면 오탐이 난다.** 소상공인 기사는 상호가 아니라 **대표 이름**으로
   나가는 경우가 흔하다(캔버스가든 × 경향신문 — 본문에 상호 0회, 대표 실명 13회. 진짜 기사였다).
   → 본문에 상호가 없다고 창작으로 단정하지 말고, 사람 이름·주소·제품명으로 재대조한다.
   ※ 대조에 실명을 **쓰는 건** 되지만, 소개서 본문에 실명을 **쓰는 건 금지**(개인정보, 아래 §금지).
2. ⚠️ **매체 원문이 아니라 자기 인스타 게시물이 링크로 걸린 경우**가 있다(계단뿌셔클럽 BBC).
   "소개 보기"의 기대와 어긋나니 그대로 두지 말고 ③에서 대표에게 판단을 묻는다.
3. ⚠️ **블로그 후기는 press가 아니다** — 07-22 판정상 activity로 라우팅되는데 실제 prod 데이터엔
   press에 들어가 있다(두더지요가원 3건, 컨시어지 수동 추가로 보임). **정책과 데이터가 어긋난 상태**라
   새로 넣지 말고, 이미 있는 것은 ③에서 옮길지 물어본다.
- ⛔**URL 창작 절대 금지.** 링크는 검색 결과에 실제로 보인 것만 글자 그대로. 도메인만 보고 조립하지 않는다.
- ⭐**매체명도 창작 금지** — 정확히 모르면 그 항목을 뺀다. 단 **링크 없는 매체(지역 지류신문·사보)는 정상**이다.
  링크가 없다고 그 소개가 가짜인 건 아니다(제품 정책 ⑦: press는 링크 없어도 노출, 매체명 창작만 금지).

## ② 사장님 목소리 리서치 (유료 크롤 0콜)

**위저드를 다시 돌리지 않는다** — 보강은 폼 직접 수정이므로 Gemini 콜이 0이다.
리서치는 전부 무료 수단(WebSearch·WebFetch·curl·브라우저 탭):

우선순위 순서 (사장님이 직접 쓴 글일수록 가치가 높다):

1. **인스타그램** — ⭐**meta는 `facebookexternalhit` UA일 때만 나온다**(curl·브라우저 공통, 실측).
   일반 UA는 200이 떨어져도 meta가 비어 있다. 프로필 `meta[name=description]`=바이오 전문,
   게시물 `og:title`=캡션 전문. **08-02 재실측: 이 경로는 여전히 살아 있다**(200 + 바이오 전문).
   - 🪤**바이오 추출 함정 3겹(08-02, 두 팀이 각각 헛짚음).** 하나만 고치면 "태그는 찾았는데 내용이 없다"로
     또 막힌다. **제품 코드(`lib/instagram.ts` `metaContent`)는 셋 다 처리하고 있으니 그걸 베껴라** —
     일회성 `curl`+`grep`으로 확인하다 빠지는 함정이다.
     1. **속성 순서** — 실제 HTML은 `<meta content="…" name="description">`로 **`content`가 `name`보다 앞**이다.
        `<meta name="description" content="` 로 시작하는 정규식은 안 걸린다. 양방향 패턴을 써라.
     2. **HTML 엔티티** — 값이 `&#x2739; &#xc6b0;&#xc5f0;&#xd55c;…`로 인코딩돼 있어 **한글로 grep하면 0건**이다.
        디코드 전에 "바이오가 없다"고 판정하지 마라.
     3. **`og:description`은 바이오가 아니다** — 거긴 `14K Followers, 842 Following, 520 Posts…`
        팔로워 수 문구만 들어 있다. **바이오 전문은 `name="description"` 쪽에만** 있다. 둘을 헷갈리면 빈손이 된다.
     ⚠️ 이 세 겹 때문에 **멀쩡한 경로를 "인스타가 막았다"로 오진**하기 쉽다(08-02 실제 발생).
   - ⚠️**추출 성공 ≠ 쓸 수 있는 재료. 그리고 바이오는 필드가 아니라 줄 단위로 갈라야 한다**(08-02 확립).
     같은 `description` 한 덩어리 안에 성격이 전혀 다른 줄이 섞여 있다 — 통째로 재료 취급하면 사고 난다.

     | 줄의 성격 | 처리 | 실측 예 |
     |---|---|---|
     | **정체성 문장** | ⭕최고급 재료 | canga 1줄 `우연한 재치를 찾아 옷의 조각을 잇습니다` |
     | **연락처·부계정 핸들** | ⛔**버린다** | canga 2·3줄 `제작/협업문의…contact@…` `@jyogak_workshop_archive` |
     | **영업시간·휴무** | ⛔**버린다**(유통기한 정보 금지) | 콜렉트마이페이보릿 = **4줄 전부** → 재료 0건 |

     - 🪤**"연락처는 trust로 옮기면 되지"는 틀렸다** — `TrustSignals`엔 **이메일 필드가 없다**

  ⭕패턴화는 허용: "매달 새로운 기획전을 열고 있어요". ⚠️'낮술·혼술·브런치'는 **분위기지 영업시간이 아니다**(지우지 말 것).

  1순위지만 **자체 기획 팝업·일회성 행사도 가치가 보이면 올린다.** 반복은 가중치. 상세 = §②-B.

- ⭐**지역검색 결과는 '한 업체'가 아니라 '목록'이다** — 줄마다 다른 업체다. 링크·업종을 쓸 땐 그 행의 상호를 재확인.
  (안 하면 이웃 가게 링크가 대표 URL로 붙는다.)

### 문안을 쓸 때의 어투 규칙 (`enrich.ts` `OPTIONS_SYSTEM`과 같은 계약)

- ⭐**1인칭 사장 시점** — 문장 주어로 브랜드명·'이곳'·'이 브랜드' 금지("○○는 ~해요" 금지),
  브랜드명을 문장에 넣지 않는다. 주어는 저희/우리 또는 생략(⚠️'저희는' 반복 금지, 변주).
- ⭐**어미**: 한 줄 소개는 **해요체 고정**(행위+진행형 — "~을 만들고 있어요"). 감성 서술어(선사해요·전해요)·
  권유형(만나보세요·함께해요) 금지. **자세히 소개는 기능 기반 혼합체** — 믿음·확정 선언=`~합니다`,
  🆕**대표 퇴고 4규칙(08-06 로컬페이지)**: ①짧은 문장 3~4개 연속 금지 — 하나는 `~하고 있고,`로 이어 긴 문장을 만든다
  ②연결 어미 **`~있고요/~고요` 금지**(잇거나 `~있어요`로 끝내거나) ③본문 속 **'닫다' 은유 금지**("하루를 닫는"❌ → "하루를 마무리하는")
  ④활동·콜라보 desc에 **자기 해설 꼬리 금지**("~려는 시도였습니다"❌ — 사실 문장으로 끝나도 된다) +
  ⭐**브랜드 자기 어휘 우선**(브랜드가 '로컬'이라 쓰면 '지역'으로 번역하지 않기) · offers의 미경험 협업은 **"~만들어 볼 수 있을 것 같아요"** 가능성 문형.
  이유·부연=`~이에요/예요`, 지향=`~바랍니다`. 합니다만 연속=사보, 에요만 연속=수다.
- ⭐**현재형** — 지금도 하는 일은 `~하고 있어요 / 이어가고 있어요`. 과거형은 정말 끝난 사건에만.
  🚨⭐**과거형만 막으면 부족하다 — '완결형'도 같이 막아라**(대표 지시 08-02, AI크롤 결과에서 나옴).
  `만듭니다` · `완성했습니다` · `구축했습니다` · `마련했습니다` · `이루어 냈습니다` · `정착시켰습니다`는
  문법상 현재형이어도 **한 번에 끝낸 것처럼** 읽혀 브랜드가 멈춘 인상을 준다.
  · ⛔`…실질적인 계기를 만듭니다` → ⭕`…만들어 가고 있습니다`
  · ⛔`…확신으로 바꿔주는 가이드를 완성했습니다` → ⭕`…완성해 가고 있습니다`
  · **닫기 전에 "이 일이 지금도 계속되나?"를 묻고 서술어를 고른다.** 정말 끝난 사건(지난 콜라보·행사·수상)만 과거형.
  🪤**아래 '의미로 닫기' 예시(`자리를 만들었습니다`)를 그대로 복사하지 마라** — 그건 *끝난 행사*라서 과거형이 맞았던 것이다.
  콜라보는 한 항목 안에서 시제를 분리한다(협약=과거형 / 그 결과로 지금 하는 일=현재형).
- ⛔**상투어 블랙리스트**: 믿습니다 · 응원합니다 · 빛나는 · 든든한 버팀목 · 소중한 · 특별한 · 함께 성장 ·
  꿈을 향해 · 첫걸음/시작점 · 긍정적인 에너지 · 선사합니다.
- 🚨⭐⭐**먼저 — 어느 칸에 쓰는 문안인지부터 보라.** 규칙이 칸마다 다르고, **이걸 섞으면 사고가 난다**(08-02 캔앤코르크에서 실제로 냈다).

  | 프로그램에 **참여했어요** | 프로그램에 **멘토 디자이너로 참여했어요** |

  ⭐**역할 이름이 박히면 「이 사람에게 무엇을 맡길 수 있나」가 읽힌다 — 그게 콜라보 제안의 재료다.**
  🪤「참여했어요」로 끝내면 한 일은 적혔는데 **맡길 수 있는 것이 안 적힌다.** 우리 제품에선 그게 전부다.
  ⛔**나열은 둘까지** — 캡션의 「남기는 것 4가지」를 다 옮겼다가 대표가 둘로 줄였다.

  ### ⭐⭐ 초안 단계에서 미리 맞추는 것 — 대표 퇴고 패턴 11 (08-21 파랑~ 전수 대조)
  내가 쓴 초안 22개와 대표 확정본을 나란히 놓고 대조해 뽑았다. **고친 결과가 아니라 「고치기 전에 맞출 것」이다.**
  정본·예문 = [[브랜드-보이스]] §14.

  | | 패턴 | 초안 → 확정 |
  |---|---|---|
  | ① | **순서: 유래 → 의미 → 방식** | 시간·인원·장소는 **맨 뒤**로 민다 |
  | ② | **압축 명사구를 지운다** | 「애장품과 소장품 사이.」 통째 삭제 — 멋있지만 뜻이 늦게 온다 |

  | ⑤ | **의문문을 서술로** | 「어떻게 기억해야 할까요.」 → 「어떻게 기억할지에 대한 **고민으로**」 |
  | ⑥ | **형식을 명명하며 닫는다** | 「함께 살펴요」 → 「살펴보는 **워크숍이에요**」 |
  | ⑦ | **한 항목 안에서 시제를 나눈다** | 「참여하고 있어요…이어 가고 있습니다」 → 「**참여했어요**…이어 가고 있습니다」 |
  | ⑧ | **「그때 뭘 했나」→「지금 어디까지」** | 「가을엔 …에서 이어 갔습니다」 → 「**지금은 3기까지 진행했어요**」 |
  | ⑨ | **얇으면 늘리고 지어냈으면 자른다** | 전시명상 76자 → **140자**(절차 추가) / 내가 붙인 착지 문단은 **삭제** |
  | ⑩ | **두 문단이 기본** | 앞=무엇인가 / 뒤=어떻게 하는가. 수렴점 **100~180자 · 최대 2문단** |
  | ⑪ | **제목엔 «행위»가 들어간다** | 「…—감상법을 담은 책」 → 「…**출간** — …」. 명사로 끝나면 사물이지 활동이 아니다 |

  🪤**그리고 내가 파랑~ 건에서 다섯 항목을 «같은 병»으로 틀렸다** — **한 회차만 보고 프로그램 전체인 줄 알았다.**
  준비운동은 시즌3만, 오뉴는 도슨트 한 번만, 히스테리안은 워킹클럽만 잡혀 있었다. 원문을 열면 그 위에 **시즌 전체·관계 3층**이 있었다.
  ⭐**시즌제·정기 프로그램은 최신 회차만 보면 반드시 틀린다** — 문안 쓰기 전에 그 이름으로 **전 기간을 다시 훑어라**.

  - ⭕⭐⭐**닫는 정답 문형 = 형식을 명명한다**(08-02 대표 실제 문장에서 증류).
    **[내용 서술] + [○○ 행사·모임·프로그램·클래스·팝업·장터·콜라보]를 진행했어요 / 운영하고 있어요**로 닫는다.
    · ⭕`…다양한 장르를 즐겨보는 New Jack Saturday 행사를 진행했어요`
    · ⭕`…이 달에 추천할 와인리스트를 구성해 월간 장터 프로그램을 운영하고 있어요`
    · ⭕`…산책과 식사를 나누며 이웃과 연결되어 보는 콜라보를 진행했어요`
  - ⛔**감상의 명사화는 금지** — `~하는 자리를/시간을 만들었습니다`.
    🪤**같은 명사로 닫아도 성격이 다르다** — **형식(행사·모임·프로그램)은 분류라 단단하고, 감상(자리·시간)은 붕 뜬다.**
    의미를 담고 싶으면 동사로: ⭕`한 캔의 경험을 함께 즐기는 시간으로 확장하고 있습니다`
  - ⭐**제목에 형식어를 붙인다**(같은 출처) — 고유명은 살리고 뒤에 **팝업·모임·클래스·장터·프로그램·생산**을 붙여
    **제목만 봐도 무엇인지** 알게 한다. ⭕`우리집 살구나무 팝업` · `세나와 일본어로 인사하기 모임` ·
    `쏠티팬트리 - 캔 통조림 직접 생산`. ⛔고유명만 덩그러니 / ⛔**할인·프로모션 명칭**(`도전! 전국최저가`)은 제목에서 뺀다.
  - 💡**기능 정보는 문장 말고 칩으로**(대표 해법 08-02) — 대관·촬영 가능 같은 건 공간 desc에 욱여넣지 말고
    `클래스 진행`·`촬영 친화`·`팝업 경험` 처럼 **칩**으로 세운다. 문장은 짧게, 스캔용 정보는 칩으로.
  - ⛔**서사·회고·감정 서술 금지**(짧은 칸 한정) — "그 한 입이 오래 남았고", "어찌나 잘 그리시는지"는 `story`의 몫이다.
  - 🪤**대표 원문(08-02)**: *"활동은 ~했었어요·하고 있습니다처럼 **현재형/과거형으로 활동을 기술**하는 게 맞아. 무슨 감정 표현을 그렇게 많이 썼냐구."*
  - 정본 = `enrich.ts` `OPTIONS_SYSTEM` activityHints 항목 + 자기검열 [3차: 길이].

- ⭐⭐**닫는 문장은 '의미'로 — ⚠️자세히 소개·시작 이야기 전용**(2026-08-02 대표가 내 문안을 직접 퇴고해 확립. 정본 = 볼트 [[브랜드-보이스]] §9).
  착지점이 **세 종류**인데, 셋을 구분 못 하면 글이 사실은 정확한데 **얇게** 읽힌다:

  | | 문형 | 판정 |
  |---|---|---|
  | ⛔ | "빛나는 미래를 응원합니다" | 상투어. 금지 |
  | △ | "매번 새로운 주제를 정해 진행했어요" | 사실에서 멈춤. **얇다** |
  | ⭕ | "…오며가며 만난 사람들이 편하게 대화하는 **자리를 만들었습니다**" | 그래서 무엇이 생겼는지로 닫음 |

  - ⭕는 ⛔처럼 감정어를 얹는 게 아니라 **그 자리에서 실제로 생긴 것**(자리·시간·계기·관계)에 이름을 붙이는 것이다.
    근거가 없으면 억지로 붙이지 말고 사실로 끝내라 — **지어낸 의미는 상투어와 같다.**
  - 🔎**자기점검**: 문안을 다 쓴 뒤 **각 항목의 마지막 문장만 따로 모아 읽어라.** 전부 사실로 끝나면 얇은 것이다.
- ⭐**경험이 먼저, 제품은 그다음** — 특히 **한 줄 소개**. "무엇을 파는가"가 아니라 **"사람들이 왜 여기 머무는가"**.
  ⛔"좋은 커피와 음악, 굿즈를 판매하고 있어요"(품목 나열) → ⭕"성북천 곁에서 좋은 커피와 음악, 사람들의 이야기가
  머무는 공간을 만들고 있어요". 읽는 사람은 **콜라보 상대**다 — 매력과 *함께할 가능성*이 느껴져야 한다.
- ⭐**사람이 문장 가까이에** — 사람들이·이웃과·손님들과. 공간과 제품만 나오는 문단은 정확해도 차갑게 읽힌다.
- ⭐**콜라보 제목 문형 = `[파트너명] - [내용] + 형식어(콜라보·프로모션·프로젝트·파트너십)`**(대표 퇴고 3건에서 확정 08-06 — 구 "프로젝트명으로" 규칙의 진화형: 파트너를 빼는 게 아니라 **앞세우고 무엇을 했는지가 따라붙는다**).
  ⭕`트립고잉 - 공동 이벤트 콜라보` · `할라마난 레지던스 - 숙박권 프로모션 콜라보` · `로컬 아티스트 - 터틀즈 벽화 프로젝트`
  예외: 고유 행사명(`미스 바디안 2026 공식 파트너십`)·기관 나열(`필리핀 관광부 · 제주항공 공동 프로모션`)은 그대로. ⛔파트너명만 덩그러니는 여전히 금지.
- ⭐**활동 제목 = `[고유명] + [행위]` — 부제(`— …`)는 «허용»된다**(08-21 파랑~ 확정본이 08-06 규칙을 갱신).
  🚨**전엔 「부제 금지」라고만 적혀 있어 다음 사람이 부제를 통째로 못 쓰는 걸로 읽었다**(08-23 2팀 보고).
  실제로 대표가 한 일은 **부제를 지운 게 아니라 앞에 «행위»를 더한 것**이다:
  `『박물관은 조용하지 않다』 — 감상법을 담은 책` → **`『박물관은 조용하지 않다』 출간 — …`**
  · ⭕**허용되는 부제 = 「그게 뭔지」를 알려주는 것** — `— 시즌제 감상 모임` · `— 매달 마지막 일요일, 각자 할 일을 하는 모임` · `— 필자로 참여` · `— 북토크 in 제주`
  · ⛔**금지되는 부제 = 「의미를 지어낸 것」** — `— ~하는 일` · `— ~하는 공간` 같은 감상. ('왜'는 본문 몫)
  · 🪤**명사로 끝나면 그건 사물이지 활동이 아니다.** 제목엔 행위(출간·운영·참여·진행)가 들어간다.
  · 🔗**콜라보 제목은 「파트너 — 프로젝트명」으로 통일**(파랑~ 확정본 전량이 이 꼴). 형식어는 변주(운영·제작·진행·프로그램·클래스·생산). ⭕`가이드와 함께하는 세부·보홀 정기 청소 프로그램`
  (`collabHistory.partner`엔 상대가 들어가지만, 항목 제목으로 읽히는 문안은 무엇을 했는지가 보여야 한다.)
- ⛔**따옴표 절제** — 키워드·별칭을 따옴표로 감싸지 않는다. 실제 인용(사장 발언·수상명·공식 프로그램명)에만.
- ⭐**차별화 테스트** — 다른 업체에 붙여도 말이 되면 지운다. Why도 구체에 뿌리내려야 한다("정성을 담습니다" 금지).
- ⭐**대표 톤 확정(07-23)**: 인터뷰 원문을 통짜로 이식하면 "오글거린다". **미션·정체성만 담백하게 의역**하고,
  사장님 1인칭 육성(관장의 편지 등)은 담백한 미션 기원으로 증류한다.
- 🆕🚨**「의미로 닫아라」는 「의미를 지어내라」가 아니다**(08-18 대표 퇴고). 착지점을 **창작**해 넣었더니
  (*"찍는 사람과 쓰는 사람이 나뉘지 않으니 처음 본 장면이 마지막 지면까지 그대로 갑니다"*) 대표가 **통째로 지웠다** —
  브랜드가 한 말이 아니고, 자기 강점을 자기 입으로 선언하는 꼴이라 자랑으로 읽힌다.
  ⭕**대신 이미 문단에 있던 사실 하나(「책의 뒤편에 함께 만든 이로 이름을 올리며」)를 끝자리로 옮겼다** —
  사실이면서 동시에 의미인 문장이다. ⭐**착지점은 만드는 게 아니라 「가진 것 중에서 고르고 옮기는」 것.**
  🪤그러려면 **"이 문장은 어느 일의 끝인가"**를 물어야 한다(그 문장은 원래 엉뚱한 문단에 있었다).

  두 번 지어냈지만, 대표는 본인 프로젝트명 「**렌탈** 전종원」에서 온 **「렌탈 일원」**을 택했다.
  판정은 예시 오염과 같은 축 — **「그 말의 출처가 입력인가」**. 내가 만든 조어는 후보에도 못 낀다.
- 🆕🎭**역할 동사를 사실과 대조하라**(08-18). *「동행을 깊이 있게 **이끌어** 갑니다」* → 대표 정정 *「깊은 동행을 **이어가기도** 합니다」*.
  **남의 팀에 팀원으로 들어가는 일에 「이끈다」는 앞뒤가 안 맞는다.** [[who-authored-the-field]]의 *"우리가 맡은 몫이 뭔가"*를
  **동사에도** 적용 — 주도(이끌다·기획하다)인가 참여(맡다·함께하다·이어가다)인가. 크게 쓰면 좋아 보이지만 거짓이 된다.
- 🆕**같은 고유명을 세 칸에 반복하지 않는다**(08-18) — 「렌탈 전종원」이 한 줄 소개·자세히 소개·활동 제목에 세 번 나오자
  대표가 가운데를 뺐다. 소개서는 한 화면에서 위아래로 읽힌다. **칸을 따로 채우지 말고 위에서 읽은 것을 전제로 써라.**
  거꾸로 **한 줄 소개에서 세운 구조(「주로 ~ 가끔은 ~」)를 자세히 소개가 이어받으면** 글이 저절로 정돈된다.

## ③ 보강안 보고 ⛔하드 게이트⛔

대표에게 섹션별 **현재 → 제안 → 출처** 표로 보고한다. 포함할 것:

- 수정 제안 (문안 전문 — "이렇게 바꾸겠다"를 실제 최종 문장으로)
- **삭제·이동 제안** (콜라보 정합성 위반, 활동↔콜라보 오분류, 오정보, 핸들 오류, press 오라우팅 등)
- 판단 필요 질문 (확신 없는 항목은 제안하지 말고 물어본다)
- 반영 안 한 리서치 소재와 그 이유 (대표가 뒤집을 수 있게)
- ⭐제안 문안이 위 어투 규칙(상투어·따옴표·시제·1인칭)을 통과했는지 **출력 직전 자기점검**을 한 번 돌린다.

### ⭐먼저 — 저장 가능한 세션인지 (2026-07-23 실증, 이거 몰라서 오래 헤맴)
저장(`updateMakerAction`)은 **소유자 세션 또는 수정 비번**을 서버에서 재검증한다
(`maker.ownerUserId === getSessionUserId()` — 둘 다 **정수**, 07-25 uuid→user_id 전환).
아래에 걸리면 편집 폼은 열리지만 **저장 POST가 조용히 abort되고 커밋 안 된다**(에러 표시 없이 `/register?edit`에 머묾).

1. **세션(쓰기 토큰) 만료** — Claude 내장 브라우저(`mcp__Claude_Browser__*`)는 시간 지나면 세션 만료.
   `/my`는 쿠키만 읽어(getSession) "로그인됨"으로 보여도, 저장은 서버 재검증(getUser)이라 만료 시 실패.
   **로컬페이지는 토큰 싱싱할 때 저장됐고, 한 시간여 뒤 같은 창에선 owned 소개서조차 전부 실패했다.**
   → **해결: 대표의 실제 크롬을 `mcp__claude-in-chrome__*`로 조종한다.** `list_connected_browsers`로 찾고,
   `tabs_context_mcp{createIfEmpty:true}`로 새 탭 → `/my`가 `/login`으로 튕기면 대표가 그 창에서 **직접 로그인**
   (자동완성돼 있어도 로그인 제출은 대표가 누름 — 비번은 에이전트가 안 만짐) → fresh 세션 → 저장 정상.
2. **미소유(비회원 생성) 소개서** — `/my`에 안 뜨면 대표 계정 소유가 아니다.
   편집 폼은 공개라 열리지만 저장은 소유자 체크로 막힘.
   → **해결: 먼저 소유자 귀속**(대표가 Supabase SQL, user_id 몰라도 됨):
   ```sql
   UPDATE brands SET owner_user_id = (SELECT user_id FROM users WHERE email = '<대표 계정 이메일>')
   WHERE slug='<target-slug>';
   ```
   🚨**08-16 수정 — 옛 예시(`… FROM brands WHERE slug='m-1vv8kj'`)를 쓰지 마라.**
   그 방식은 *"이미 소유된 소개서의 주인을 복사한다"*였는데, **참조 대상이 낡으면 조용히 `NULL`을 넣는다**
   (= 소유권이 소리 없이 풀린다). 실제로 `m-1vv8kj`는 지금 「로컬페이지_아카이빙」(inactive)이고,
   살아 있는 로컬페이지(`m-vzrlhz`)는 **08-16에 사장님 계정으로 이관돼 더는 우리 것이 아니다.**
   ⭐**남의 행을 경유하지 말고 이메일로 직접 잡는다.** 절차 정본 = **[[소개서-비번-소유권-런북]]**(대조 쿼리·확인 4종 포함).
3. **수정 비번 경로 — ⚠️미귀속 소개서 전용이 됐다(08-06 2팀 #109)** — `updateMakerAction(slug, payload, password)`의
   비번 저장은 **`owner_user_id`가 비어 있을 때만** 허용된다. **주인이 붙는 순간 옛 관리비번은 무효**
   (귀속 후에도 비번 아는 쪽이 남의 소개서를 고칠 수 있던 구멍을 막음). 판정 순서 = **"주인 먼저, 비번 나중"**.
   → 넘겨받은(귀속된) 소개서는 이 경로가 없다 — 소유자 세션(위 1)이나 귀속 SQL(위 2)로 간다.
   비번 설정·소유권 이전 SQL은 **Obsidian [[소개서-비번-소유권-런북]]** 참조
   (해시 = 솔트 없는 SHA-256, Postgres `encode(sha256(convert_to(pw,'UTF8')),'hex')`로 동일값 재현).
   ⛔비번 문자열을 에이전트가 만들거나 대신 입력하지 않는다 — SQL은 대표가 SQL Editor에서 직접.

⚠️ **사진·블록 많아서 안 되는 게 아니다** — 사진은 Storage URL이라 payload 작다. 저장 실패=위 1~3을 의심하라(오귀인 주의).

### 🆕 보강이 Brand DNA·콜라보 리포트에 미치는 영향까지 확인한다 (07-26 배포 이후)
