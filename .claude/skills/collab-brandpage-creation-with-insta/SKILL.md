# collab-brandpage-creation-with-insta — 리서치 먼저, 생성은 그다음

> **한 줄**: 인스타·블로그·브런치를 **전량 먼저 읽고**, 그 결과를 **폼에 직접 넣는다.**
> ⭐**위저드는 돌리지 않는다**(08-21 확정) — 위저드는 우리 수확본을 못 읽어서 더 얕은 결과에 돈만 든다.
> 이 스킬은 오케스트레이터다 — 세부 기법의 정본은 [[collab-brandpage-creation-basic]]·[[collab-page-enrich]] 해당 절.
> ✅**08-21 파랑~ 님(지인 아닌 첫 고객) 건에서 리서치→발행까지 완주**했다. 그때 나온 실전은 §②에.

## 왜 이 순서인가 (2026-08-05 대표 설계 + 1팀 검증)

1. **칩 선택에 근거가 생긴다.** 구 모드 A의 칩 기준은 "넓게" 한 단어뿐이었다(사람 감).
   브리프가 먼저 있으면 **근거 있는 것만** 고르고, 크롤이 놓친 건 "직접 추가"로 넣는다.
2. **사진 1장 필수(08-05 배포)와 정합.** 신규 등록은 이제 사진 없이 저장이 안 된다 —
   구 모드 A(프리필→바로 저장)는 **그대로는 깨진다.** 리서치가 먼저면 저장 시점에 사진이 이미 폴더에 있다.
3. **리서치 한 번을 끝까지 쓴다.** 브리프 → 후보 아티팩트 → 문안 → 사진 선별이 **같은 수확물** 하나를 계속 쓴다.

⚠️ **위저드의 AI 크롤은 우리 리서치를 못 읽는다** — 이것이 08-21에 위저드를 폐기한 이유다.
그전에는 「사람이 만지는 지점(칩·별표·게이트)에서 회수한다」였는데, **폼에 직접 넣으면 회수할 것도 없다.**
위저드는 [[collab-brandpage-creation-basic]] 모드 A(하한 측정)로만 남는다.

## 전체 지도

```
⓪ 입력·동의 확인 → ① 사전 리서치(브리프) → ② 폼 직접 입력(⭐위저드 안 씀·유료 0콜)
→ ③ 후보 아티팩트 → 대표 판정 → ④ 문안 확정 + 저장 → ⑤ 사진 회수 → ⑥ 대표 선별·발행·이관
```

대표 개입 지점 = **4곳**: ⓪입력 · ③후보 판정 · ⑤사진 선별 · ⑥발행 확인.
**유료 콜 = 0.** 리서치도 폼 입력도 전부 무료(브라우저·HTTP)다.

⚠️**2026-08-21 이전 판에는 「② 위저드 생성(유료 1콜)」이 있었다.** 폐기한 이유는 §②에.

## ⓪ 입력 + 동의 확인

대표가 준다: **상호 · 주소(지역) · 하는 일(업종) · 홈페이지 URL · 인스타 핸들.**
(주소·업종은 위저드 씨앗의 필수 입력이자 동명 업체 방어 — 없으면 여기서 되물어라.)

### 🚨 인스타 수확 = **전량 수확이 기본이다** (08-05 대표 확정)

**이 스킬은 동의 후에만 시작한다** — 영업 플로우가 "만들어드릴까요? → 예스"를 거친 뒤 제작에 들어가므로,
시작 시점엔 항상 동의가 있다. *"완전히 실전으로, 정확한 정보로"*(대표 원문).

**절차**: 대표가 **인스타그램 탭을 열고 본인 계정으로 로그인**해두면 → 그 세션으로 그리드 전량 열거 →
내부 웹 API로 캡션 전문·작성일·태그계정·원본 이미지 URL 조회. 기법 정본 = [[collab-page-enrich]] §②-A(콜마페 124건 실증).

- 강도 상한(정본 = [[ig-photo-tool]]): **요청 간 1~2초 · 계정당 130건/일(🔄08-05 대표 상향, 구 100) · 하루 2~3계정.**
  게시물이 그보다 많으면 최신부터 130건에서 끊고 보고한다(다음 날 이어받기).
- ⛔ 대표 세션 없이 시작하지 않는다. 로그인월 우회·UA 위장 금지. 막히면 "막혔다"고 보고.
- 🤝 **인스타 작업 전 2팀에 DM** — 레이트리밋은 IP=머신 공유(08-04 실측, 1팀 302 사건). 겹치면 서로 결과를 오염시킨다.
- (예외) 동의 **전** 사전 검토가 필요한 특수 케이스만 저강도 공개 수집(바이오+10~15개·4초) — 이 스킬의 정규 경로 아님.

## ① 사전 리서치 → 브랜드 브리프 (유료 0콜)

수확(기법 정본 = [[collab-page-enrich]] §②): 인스타 바이오·캡션(위 강도 내) + 홈페이지
+ 필요시 네이버 지역검색·기사. **진행하며 요약을 쌓는다** — 끝나면 아래 형식의 **브리프**로 정리해 대표에게 먼저 보여준다.

### 📏 홈페이지 fetch — 두 층이 따로 돈다 (08-05 코드 실측 · `src/lib/homepage.ts`)

같은 홈페이지를 **두 번 읽는다.** 층이 다르고 상한이 다르다 — 헷갈리면 "왜 모델이 이 내용을 몰랐지"를 오진한다.

| | ⓐ **이 스킬의 사전 리서치** (①, 브라우저/사람) | ⓑ **제품 서버 딥리드** (②의 위저드가 자동 실행) |
|---|---|---|
| 언제 | 위저드 **전** — 브리프 재료 | 위저드 ③에서 홈피 "맞아요" 확약 시 |
| 페이지 수 | **15~20p까지**(대표 08-05 "더 많이") — 의미 있는 페이지는 다 읽는다 | **최대 10p**(홈 포함) — 코드 고정 |
| 시간 | 사람 페이스 (수 분 — 대표 컴이라 무관) | **전체 8초** 예산·페이지당 4초(늦으면 포기) |
| 분량 | **페이지당 5,000자 · 총 50,000자**(08-05 대표 확정 — ⓑ의 ~2.8배) | 페이지당 3,500자 → **총 18,000자**에서 자름 |
| 서브 페이지 선택 | 사람이 메뉴 보고 판단 | 링크 점수제: **소개·스토리·철학 100점** > 콜라보·파트너 65 > 프로그램·서비스 60 > 뉴스·연혁 30 > 팀 25. 로그인·장바구니·약관은 차단 |
| 못 읽는 곳 | 없음(브라우저라 JS 렌더도 읽음) | 네이버 계열·modoo·인스타·페북 등 **시도 자체 안 함** + JS 렌더 사이트는 빈손 |
| 소비자 | **사람**(브리프 → 칩·별표·게이트 조작) | **모델**(생성 프롬프트에 [홈페이지—발췌]로 주입) |

- ⭐**ⓐ를 늘려도 ⓑ는 안 늘어난다** — 모델이 직접 읽는 건 ⓑ의 18,000자뿐이다. ⓐ에서 발견한 것을 모델에 전하는 통로는
  **칩 직접 추가·별표·사실 게이트**(사람 손)뿐이라는 걸 잊지 말 것.
- ⓑ의 상한을 코드에서 올리는 건 **비용·지연과 직결**이라 별도 결정 사항이다(입력이 이미 원가의 절반 — 딥리드 압축이 백로그).
  modoo·네이버 홈페이지 브랜드는 ⓑ가 0이므로 **ⓐ가 유일한 홈페이지 경로**다.
- ⓑ 확장은 **08-05 대표 문의에 "지금은 안 늘린다"로 답함** — 10p 점수제가 이미 알짜를 뽑고, 글자 확장은
  입력 원가·위저드 지연만 키운다(증거 없음, 07-27). ⏭단 **무비용 재배분 실험**은 열어둠: 총량 18,000 유지 +
  최고점 페이지(소개·스토리)만 페이지당 3,500→6,000자. **테스트 1회차에서 스냅샷 A가 얇으면 그때 근거 갖고 재론.**

```
[브랜드 브리프 — ○○○]
정체:        (무엇을 하는 곳인가 한 줄)
사장님 목소리: (바이오·캡션에서 원문 그대로 2~4개 — verbatim 후보)
⭐본인이 붙인 이름: (프로젝트명·서비스명·자기 별칭 — 원문 표기 그대로. ⑤ 문안의 1급 재료)
활동 후보:    (반복·대표 프로그램 우선, 일회성도 브랜드다움 보이면)
콜라보 후보:  (파트너명이 드러난 것만)
키워드 후보:  (칩으로 쓸 것 — 아래 ② 기준으로 미리 걸러둠)
확인된 사실:  (수상·방송·수치 등 — 별표·사실게이트 후보)
사진 후보:    (게시물 URL 목록 — ⑤에서 회수할 것)
불확실:      (확인 못 한 것 — 위저드에서 켜지 말 것)
```

### 🚨 리서치 검색은 **전문에 대고 하라** — 요약본은 검색도 못 믿는다 (08-18)

수확물의 캡션은 **잘려 있을 수 있다.** 전종원 작가님 수확본은 **400자에서 컷**돼 있었고
146건 중 **48건이 그 상한에 걸려** 있었다. 결산형 게시물(한 편에 소절 넷)은 뒤쪽 소절이 통째로 사라진다.

🪤**그래서 「그 주제 게시물은 하나뿐」이라는 오답이 나온다** — 실제로는 **4건**이었다(08-18, 「네 멋대로 해라」).
⭐**규칙 = 후보를 훑을 때가 아니라 「몇 건인가」를 답할 때는 전문을 확보하고 세라.**
- 판별: `cap.length`의 분포를 본다. **한 값에 뭉쳐 있으면 그게 컷 지점**이다(48건이 정확히 400).
- 전문 재조회 = `/api/v1/media/{id}/info/`(shortcode → base64 디코드). 48건에 1분 안쪽.
- 🔗**이 함정의 상위 규칙** = memory `index-is-not-the-source`(요약본으로 고르고 원문으로 쓴다).
  **검색까지 요약본에 대고 하면 「없다」는 결론 자체가 틀린다.**

## ② 폼 직접 입력 — **위저드를 돌리지 않는다** (대표 확정 08-21, 「ⓐ안」)

### 왜 폐기했나
- 🚨**위저드는 우리 리서치를 못 읽는다.** 자기 크롤만 본다 — 인스타 636건 전량 수확본이 있어도 소용없다
- 유료 콜인데 **우리 브리프보다 얕은 결과**가 나온다
- ⭐위저드의 남은 값은 **「고객이 혼자 만들면 어디까지 나오나」의 하한 측정**뿐이다
  (그 용도는 [[collab-brandpage-creation-basic]] 모드 A)

### 폼 구조 — 저장 전과 후가 다르다 (08-21 실측)

| 화면 | 여기서 넣는 것 |
|---|---|
| `/register` **신규** | 이름 · 한줄 · 자세히 · **사진(필수 1장)** · 찾는 유형 칩 · 찾는 설명 · 제공 설명 · 주소 · 인스타 · 대표 URL |
| 등록 버튼 누르면 뜨는 **모달** | 활동 · 콜라보 · 고객 (우하단 **「+ 추가」** 플로팅 버튼에도 같은 메뉴) |
| 저장 후 `/register?edit={slug}` | **시작 이야기**(「왜 이 브랜드를 시작하셨나요」) · **키워드 칩**(「브랜드를 표현하는 키워드」) · 블록 6종 |

🚨**시작 이야기와 키워드는 신규 화면에 없다.** 저장하고 수정 모드로 다시 들어가야 나온다.

### 개수·정렬
- **상한 활동 30 · 콜라보 30** (`src/lib/limits.ts` — 숫자를 여기 쓰지 말고 그 파일을 열어라).
  🪤스킬 문서의 낡은 숫자(5·10)를 믿고 대표께 오보한 적 있다(08-21)
- **정렬 = 「한 일의 시점」 최신순**(대표 확정 08-21). 「글을 쓴 날」이 아니다 —
  *「소개서를 보는 사람은 지금 뭘 하시나를 본다」*
- 화면엔 5개씩 보이고 나머지는 「N건 더 보기」로 접힌다(`REVEAL_STEP`)

### 조작 기법 (대표 크롬 fresh 세션에서만)
- 🚨**저장은 대표 실크롬에서만 된다.** 내장 브라우저는 폼이 다 채워져도 **저장만 조용히 실패**한다
- **텍스트**: React 네이티브 setter — `Object.getOwnPropertyDescriptor(Object.getPrototypeOf(el),'value').set.call(el,v)` 후 `input`·`change` 디스패치
- **칩**: 값 주입 후 **Enter keydown 디스패치**. ⚠️**하나씩**(연달아 넣으면 앞엣것이 씹힌다).
  선택되면 목록에서 사라지고 `✓`가 붙는다. **키워드는 10개 상한**(꽉 차면 입력칸 `disabled`)
- **카드 추가**: 「＋활동 추가」·「＋콜라보 추가」를 **간격 0.35초로 반복 클릭**해 필요한 수만큼 만든 뒤 한 번에 채운다
- **링크**: 카드마다 「＋아티클 링크 추가」를 눌러야 칸이 생긴다. **반드시 `https://` 포함 전체 URL**
  (서버가 스킴 없는 값을 조용히 버린다 — 저장은 성공하는데 링크만 사라진다)
- **콜라보 전용**: 연도 `<select>` + 유형 칩 7종 + 「+ 유형 직접 추가」
- **최종**: 「브랜드 소개서 등록하기」/「수정 완료」. 클릭 후 `/m/{slug}`로 바뀌면 성공.
  ⚠️**재클릭 남발 금지**(POST가 서로 abort). 안 넘어가면 스샷 확인 후 좌표 실클릭
- 🚨**수정 모드 진입 시 임시저장 배너가 뜨면 반드시 「저장된 내용 그대로」.**
  「이어서 쓰기」는 서버 최신본을 낡은 로컬 초안으로 덮는다

### 🔗 아티클 링크 — 고르는 기준은 하나다
활동·콜라보의 링크는 **1개뿐이고 라벨이 「아티클 보기」로 고정**돼 있다(`MakerArticle.tsx`).
⭐**그러니 「아티클 보기」라고 써 있어도 어색하지 않은 것 = 읽을 거리만** 넣는다.

1. **본인이 직접 쓴 정리 글** — 브런치 1순위, 블로그 2순위
2. 인스타는 **모집 공고 말고 「끝난 뒤 기록·후기」**
3. 파트너가 쓴 글은 마지막(남의 집이라 내려갈 수 있다)

⛔링크트리·리틀리·신청 폼은 넣지 않는다(목록이라 「아티클 보기」와 안 맞고 항목마다 같은 주소가 붙는다).
여러 개가 꼭 필요하면 **선택 블록**으로(links 3개 + 이름표 자유).

🚨**주소는 반드시 수확본에서 찾아 붙여라.** 08-21에 날짜는 데이터에서 보고 **주소는 기억으로 적어
8개를 지어냈다**(대표가 눌러보고 발견). 넣기 전 검증:
```bash
curl -A "facebookexternalhit/1.1" https://www.instagram.com/p/{code}/ | grep -c og:description
# 1 = 실재 / 0 = 없는 페이지 (HTTP는 없는 것도 200을 준다)
```

## ⑤ 사진 전체 회수 + 초안 수정

- 대표가 고른 게시물의 사진을 폴더로 회수 — 기법 정본 = [[collab-page-enrich]] §④-B(61장 0실패 실증).
- 초안 텍스트 수정·보완 = §④ 폼 조작 정본(네이티브 setter·칩 Enter·임시저장 배너 함정 포함).

### 📐 사진은 **4:3으로 잘린다** — 고르기 전에 알아야 한다 (`PhotoSlider.tsx` `aspect-[4/3]` + `object-cover`)

소개서의 모든 사진(브랜드·활동·콜라보·블록)과 콜라보 카드(`/c`)가 **4:3 고정 틀에 잘라 넣는 방식**이다.
(07-26에 1:1을 시험했다가 대표 판정으로 4:3 복귀 — 코드 주석에 남아 있다.)
- 🚨**스토리·릴스에서 회수한 9:16 세로 사진은 위아래가 크게 잘린다.** 인물 얼굴이나 글자가 위쪽에 있으면 날아간다.
  → 회수 폴더에 세로 사진이 섞였으면 **「가운데에 주인공이 있는 장」을 골라 대표에게 추천**한다.
- ⭐**컨택트 시트를 먼저 만들어 보여줘라**(PIL 6~8열 썸네일 한 장). 대표가 번호로 짚는 게 제일 빠르다 —
  파일명 번호를 시트 라벨과 일치시킬 것. 사진 판단은 대표 몫이고, 우리 몫은 **고르기 쉽게 늘어놓는 것**이다.

### 🚨 문안을 쓰기 전에 — **포인터로 두면 안 읽힌다** (08-15 사고)

문체 정본은 [[collab-page-enrich]] §「문안을 쓸 때의 어투 규칙」이다. **거기를 열어서 읽어라.**
`이 스킬로 들어오면 그 절을 안 거치고 바로 문안을 쓰게 되고, 실제로 그렇게 틀렸다`(콜마페 콜라보 2건, 대표가 두 번 되돌림).
최소한 아래 넷은 **여기서** 확인하고 간다 — 전부 그때 어긴 것들이다:

1. **활동·콜라보 desc는 한두 문장(최대 3).** 마침표를 세라. 느낌으로 판정하면 5문장이 된다.
2. **날짜·시각·가격·할인·참여조건은 쓰지 않는다.** 소개서는 계속 걸려 있어서 행사가 끝나면 틀린 정보가 된다.
3. **감상·비유·계절 묘사 금지**(짧은 칸 한정). 그건 `story`의 몫이다.
4. **닫음은 형식어** — `~팝업을/모임을/콜라보를 열었어요·진행했어요`. ⛔`~자리를/시간을 만들었습니다`.

⭐**"매력 포인트가 없다"는 지적을 길이로 갚지 마라.** 남길 것은 **그 콜라보에서만 나올 수 있는 고유 조각**
(토마토 빙수·도자기 짜이잔 같은 사물, "미용실 원장님" 같은 역할)이지 문장 수가 아니다. 판별 문장 =
**"이걸 빼면 이 콜라보가 다른 콜라보처럼 보이나?"** — 표와 전체 규칙은 enrich 스킬 해당 절에 있다.

#### (08-18 전종원 작가님) 대표 퇴고에서 반복해 걸린 다섯 가지

한 줄 소개와 자세히 소개를 대표가 각각 **세 번씩 되돌렸다.** 매번 다른 문장을 고쳤는데
**판단은 하나였다 — 내가 지어낸 것을 버리고 브랜드가 이미 가진 것을 세웠다.** 다음엔 처음부터 그렇게 쓴다.

**1. ⭐고유명은 「본인이 붙인 이름」에서 가져온다.**
「주 1회 팀원이 되는」 일을 나는 *일주일에 하루 → 1일 일원*으로 두 번 지어냈고, 대표는 **「렌탈 일원」**으로 바꿨다.
작가님 프로젝트가 「**렌탈** 전종원」이라 그 말이 이미 있었다. 내 조어는 밖에서 붙인 설명이고 이건 **본인 어휘**다.
🔗판정은 예시 오염과 같은 축 — **「그 말의 출처가 입력인가」**. ⭕본인 것이면 1급 재료, ⛔내가 만든 말이면 후보에도 못 낀다.
→ **그래서 ①브리프에 「본인이 붙인 이름」 칸을 뒀다.** 문안 쓸 때 그 칸부터 연다.

**2. 🚨「의미로 닫아라」는 「의미를 지어내라」가 아니다.**
`brandpage-copy-payoff`의 ⭕의미로 닫기를 나는 **새 문장을 창작하라**로 읽고
*"찍는 사람과 쓰는 사람이 나뉘지 않으니 처음 본 장면이 마지막 지면까지 그대로 갑니다"* 를 넣었다 — **대표가 통째로 지웠다.**
그럴듯하지만 **작가님이 한 말이 아니고**, 자기 입으로 자기 강점을 선언하는 꼴이라 자랑처럼 읽힌다.
⭐**대표가 한 일 = 이미 문단에 있던 사실 하나(「책의 뒤편에 함께 만든 이로 이름을 올리며」)를 끝자리로 옮긴 것.**
그 문장은 **사실이면서 동시에 의미**다(=스쳐 가는 외주가 아니라는 뜻). 지어낸 의미는 검증할 수 없지만 이건 책을 펴면 있다.
→ ⭕**착지점을 만들지 말고 「이미 가진 사실 중 의미가 되는 것」을 찾아 끝으로 옮겨라.** 없으면 사실로 담담히 끝내는 게 낫다.

**3. 문장이 놓인 칸이 맞는지 본다 — 옮기면 사는 문장이 있다.**
위 문장은 원래 내가 **팀원(렌탈) 문단** 끝에 뒀는데, 실은 **기록·책 만드는 일의 결말**이었다.
🪤한 문단 안에서만 고치려 들면 안 보인다. **"이 문장은 어느 일의 끝인가"를 물어라.**

**4. 같은 고유명을 세 칸에 반복하지 않는다.**
「렌탈 전종원」이 한 줄 소개·자세히 소개·활동 제목에 **세 번** 나오자 대표가 자세히 소개에서 뺐다
(「렌탈 전종원 프로젝트를 통해」 → 「프로젝트를 통해」). **주 1회·6개월만 남겨도 뭘 말하는지 통한다.**
⭐소개서는 한 화면에서 위아래로 읽힌다 — **칸을 따로 채우지 말고 「방금 위에서 읽은 것」을 전제로 써라.**

**5. 🎭역할 동사가 사실과 맞는지 검증한다.**
내가 쓴 *「소규모 브랜드 동행을 깊이 있게 **이끌어 갑니다**」* 를 대표가 *「깊은 동행을 **이어가기도 합니다**」* 로 고쳤다.
**남의 팀에 팀원으로 들어가는 일인데 「이끈다」고 쓰면 앞뒤가 안 맞는다.**
🔗[[who-authored-the-field]]의 **"우리가 맡은 몫이 뭔가"** 를 동사에도 적용하라 —
주도(이끌다·기획하다)인가 참여(함께하다·맡다·이어가다)인가. 크게 쓰면 좋아 보일 것 같지만 **거짓말이 된다.**

**+ 구조 하나**: 대표는 한 줄 소개의 **「주로 ~ 가끔은 ~」** 대비를 **자세히 소개 두 문단에도 그대로** 심었다
(문단1=주업 기록, 문단2=곁일 팀원). ⭐**한 줄 소개에서 쓴 구조를 자세히 소개가 이어받으면 글이 저절로 정돈된다.**

**+ 길이**: 한 줄 소개 상한은 20~40자인데 대표 최종본은 **54자**였다(코드에 강제 제한 없음).
⚠️**상한을 이유로 구조나 고유 어휘를 깎지 마라** — 대표는 길이보다 *주로/가끔은* 대비와 「렌탈」을 택했다.

## ⑥ 대표 마무리 → 끝 = 📸 스냅샷 B

대표가 회수 폴더에서 사진을 골라 업로드 → 저장. ⑤재검증 보고([[collab-page-enrich]] §⑤ — DNA 영향 여부 포함).

### 🔢 마무리 검증은 **항목별로 세라** — "다 넣었다"는 눈으로 안 보인다 (08-18)

대표가 사진을 다 넣고 *"싹 다 읽어봐"* 했을 때, **콜라보 두 건(뉴웨이즈·콜마페)만 0장**이었다.
폴더엔 각각 14·16장이 있었으니 **빠뜨린 것**이다. 🪤페이지를 위에서 아래로 훑으면 절대 안 보인다 —
사진이 있는 항목이 훨씬 많아서 **"잘 들어갔네"로 읽힌다.** 게다가 콜라보는 **「N건 더 보기」로 접혀** 있어 눈에도 안 띈다.

⭐**항목명 ↔ 장수를 표로 뽑아 0장을 찾아라.** 접힌 것까지 세야 하니 DOM 순서로 훑는다:

```js
// /m/{slug} 에서 — "활동 N"·"콜라보 N" 라벨과 img[alt^="브랜드 사진"]을 DOM 순서로 짝짓는다
const res=[]; let cur=null;
const w=document.createTreeWalker(document.body, NodeFilter.SHOW_ELEMENT);
for(let n=w.currentNode; n; n=w.nextNode()){
  const t = n.childElementCount===0 ? (n.textContent||'').trim() : '';
  if(/^(활동|콜라보)\s*\d+$/.test(t)) res.push(cur={label:t, imgs:0});
  if(n.tagName==='IMG' && /^브랜드 사진/.test(n.alt||'') && cur) cur.imgs++;
}
res.filter(r=>r.imgs===0)   // ← 이게 보고할 목록
```
- **0장이 정상인 항목도 있다**(사진 자체가 없는 콜라보). 회수 폴더와 대조해 **"폴더엔 있는데 0장"**만 보고한다.
- 같은 방식으로 **한 줄 소개·자세히 소개가 최신본인지**도 페이지에서 눈으로 확인한다(SQL 실행 후 캐시가 남을 수 있다).
**스냅샷 B**(최종본)와 A의 격차를 한 줄로 보고한다 — *"사람 손이 얼마나 들었나 = 이 영업을 몇 곳까지 감당하나."*
