# collab-brandpage-creation-with-insta — 리서치 먼저, 생성은 그다음

> **한 줄**: 기존 제작(위저드 먼저 → 나중에 보강)의 순서를 뒤집는다.
> **인스타·홈페이지를 먼저 읽어 "브랜드 브리프"를 만들고, 그 근거로 위저드를 조작한다.**
> 이 스킬은 오케스트레이터다 — 세부 기법의 정본은 [[collab-brandpage-creation-basic]]·[[collab-page-enrich]] 해당 절.

## 왜 이 순서인가 (2026-08-05 대표 설계 + 1팀 검증)

1. **칩 선택에 근거가 생긴다.** 구 모드 A의 칩 기준은 "넓게" 한 단어뿐이었다(사람 감).
   브리프가 먼저 있으면 **근거 있는 것만** 고르고, 크롤이 놓친 건 "직접 추가"로 넣는다.
2. **사진 1장 필수(08-05 배포)와 정합.** 신규 등록은 이제 사진 없이 저장이 안 된다 —
   구 모드 A(프리필→바로 저장)는 **그대로는 깨진다.** 리서치가 먼저면 저장 시점에 사진이 이미 폴더에 있다.
3. **리서치 한 번을 두 번 쓴다.** 위저드 조작(2단계)과 enrich 후보 선별(4단계)이 같은 수확물을 재사용 — 중복 리서치 제거.

⚠️ **위저드의 AI 크롤 자체는 우리 리서치를 못 읽는다.** 브리프가 영향을 주는 지점은 사람이 만지는 곳뿐이다 —
씨앗(지역·업종) · 칩 선택 · 직접 추가 · ⭐별표 6 · 사실 게이트 · 링크 확정. 여기서 전부 회수한다.

## 전체 지도

```
⓪ 입력·동의 확인 → ① 사전 리서치(브리프) → ② 위저드 생성(유료 1콜) → ③ 사진 1장 + 저장 = 스냅샷 A
→ ④ enrich 후보 선별(아티팩트 → 대표 픽) → ⑤ 사진 전체 회수 + 초안 수정 → ⑥ 대표 사진 업로드 → 끝 = 스냅샷 B
```

대표 개입 지점 = **3곳**: ⓪입력 · ③저장 직전 사진 1장 · ④후보 픽 + ⑥사진 업로드.
유료 콜 = **위저드 1회뿐**(조사 3~5원 + 생성 70~100원). 나머지 전부 무료(브라우저·HTTP).

## ⓪ 입력 + 동의 확인

대표가 준다: **상호 · 주소(지역) · 하는 일(업종) · 홈페이지 URL · 인스타 핸들.**
(주소·업종은 위저드 씨앗의 필수 입력이자 동명 업체 방어 — 없으면 여기서 되물어라.)

### 🚨 인스타 수확 = **전량 수확이 기본이다** (08-05 대표 확정)

**이 스킬은 동의 후에만 시작한다** — 영업 플로우가 "만들어드릴까요? → 예스"를 거친 뒤 제작에 들어가므로,
시작 시점엔 항상 동의가 있다. *"완전히 실전으로, 정확한 정보로"*(대표 원문).

**절차**: 대표가 **인스타그램 탭을 열고 본인 계정으로 로그인**해두면 → 그 세션으로 그리드 전량 열거 →
내부 웹 API로 캡션 전문·작성일·태그계정·원본 이미지 URL 조회. 기법 정본 = [[collab-page-enrich]] §②-A(콜마페 124건 실증).

- 강도 상한(정본 = [[ig-photo-tool]]): **요청 간 1~2초 · 계정당 100건/일 · 하루 2~3계정.**
  게시물이 그보다 많으면 최신부터 100건에서 끊고 보고한다(다음 날 이어받기).
- ⛔ 대표 세션 없이 시작하지 않는다. 로그인월 우회·UA 위장 금지. 막히면 "막혔다"고 보고.
- 🤝 **인스타 작업 전 2팀에 DM** — 레이트리밋은 IP=머신 공유(08-04 실측, 1팀 302 사건). 겹치면 서로 결과를 오염시킨다.
- (예외) 동의 **전** 사전 검토가 필요한 특수 케이스만 저강도 공개 수집(바이오+10~15개·4초) — 이 스킬의 정규 경로 아님.

## ① 사전 리서치 → 브랜드 브리프 (유료 0콜)

수확(기법 정본 = [[collab-page-enrich]] §②): 인스타 바이오·캡션(위 강도 내) + 홈페이지
+ 필요시 네이버 지역검색·기사. **진행하며 요약을 쌓는다** — 끝나면 아래 형식의 **브리프**로 정리해 대표에게 먼저 보여준다.

### 📏 홈페이지 fetch — 두 층이 따로 돈다 (08-05 코드 실측 · `src/lib/homepage.ts`)

같은 홈페이지를 **두 번 읽는다.** 층이 다르고 상한이 다르다 — 헷갈리면 "왜 모델이 이 내용을 몰랐지"를 오진한다.

| | ⓐ **이 스킬의 사전 리서치** (①, 브라우저/사람) | ⓑ **제품 서버 딥리드** (②의 위저드가 자동 실행) |
|---|---|---|
| 언제 | 위저드 **전** — 브리프 재료 | 위저드 ③에서 홈피 "맞아요" 확약 시 |
| 페이지 수 | **상한 없음 — 15~20p까지 권장**(대표 08-05 "더 많이 해도 될 것 같다") | **최대 10p**(홈 포함) — 코드 고정 |
| 시간 | 사람 페이스 (수 분) | **전체 8초** 예산·페이지당 4초(늦으면 포기) |
| 분량 | 제한 없음 (브리프로 증류) | 페이지당 3,500자 → **총 18,000자**에서 자름 |
| 서브 페이지 선택 | 사람이 메뉴 보고 판단 | 링크 점수제: **소개·스토리·철학 100점** > 콜라보·파트너 65 > 프로그램·서비스 60 > 뉴스·연혁 30 > 팀 25. 로그인·장바구니·약관은 차단 |
| 못 읽는 곳 | 없음(브라우저라 JS 렌더도 읽음) | 네이버 계열·modoo·인스타·페북 등 **시도 자체 안 함** + JS 렌더 사이트는 빈손 |
| 소비자 | **사람**(브리프 → 칩·별표·게이트 조작) | **모델**(생성 프롬프트에 [홈페이지—발췌]로 주입) |

- ⭐**ⓐ를 늘려도 ⓑ는 안 늘어난다** — 모델이 직접 읽는 건 ⓑ의 18,000자뿐이다. ⓐ에서 발견한 것을 모델에 전하는 통로는
  **칩 직접 추가·별표·사실 게이트**(사람 손)뿐이라는 걸 잊지 말 것.
- ⓑ의 상한을 코드에서 올리는 건 **비용·지연과 직결**이라 별도 결정 사항이다(입력이 이미 원가의 절반 — 딥리드 압축이 백로그).
  modoo·네이버 홈페이지 브랜드는 ⓑ가 0이므로 **ⓐ가 유일한 홈페이지 경로**다.

```
[브랜드 브리프 — ○○○]
정체:        (무엇을 하는 곳인가 한 줄)
사장님 목소리: (바이오·캡션에서 원문 그대로 2~4개 — verbatim 후보)
활동 후보:    (반복·대표 프로그램 우선, 일회성도 브랜드다움 보이면)
콜라보 후보:  (파트너명이 드러난 것만)
키워드 후보:  (칩으로 쓸 것 — 아래 ② 기준으로 미리 걸러둠)
확인된 사실:  (수상·방송·수치 등 — 별표·사실게이트 후보)
사진 후보:    (게시물 URL 목록 — ⑤에서 회수할 것)
불확실:      (확인 못 한 것 — 위저드에서 켜지 말 것)
```

## ② 위저드 생성 (유료 1콜 — 대표 승인 후)

`https://collab5.co.kr/register` → `✨ 시작하기`. 절차 정본 = [[collab-brandpage-creation-basic]] §1단계.
**브리프를 옆에 두고** 각 스텝을 조작한다:

| 스텝 | 브리프를 이렇게 쓴다 |
|---|---|
| ⓪ 씨앗 | 지역·업종 = 대표 입력 그대로 |
| ① 칩 | ⭐**아래 선정 기준** — "넓게"는 폐기 |
| ② 별표·사실 게이트 | 별표 6 = 브리프 「확인된 사실」 상위부터. 게이트는 **브리프에서 확인된 것만** 켠다(불확실 항목은 끄기) |
| ③ 링크 확정 | 입력받은 인스타·홈피로 "맞아요" → 서버 바이오 fetch + 홈피 딥리드가 돈다 |

### ⭐ 칩 선정 기준 (구 "넓게"를 대체 — 08-05 신설)

1. **브리프에 근거가 있는 것만** 고른다. 근거를 못 대는 칩은 그럴싸해도 버린다.
2. **서로 다른 축 4개 이상**을 커버한다(정체·분위기·협업방식·가치·공간·생산·고객·지역성…) —
   상한 10개를 한 축으로 채우면 소개서도 얇고 **리포트 thin 가드**(축 4 미만 = 리포트 미생성)에 걸린다.
3. 겹침은 **가족 통합**(뿌리 칩 하나만) — 07-22 칩 겹침 정책 그대로.
4. 크롤이 못 캐온 핵심 정체성은 **"직접 추가"**로 넣는다(브리프 근거 필수).
5. 고른 칩과 그 근거를 **기록으로 남긴다** — 결과가 나쁠 때 "칩 탓인지 파이프라인 탓인지" 가릴 수 있게.

## ③ 사진 1장 + 저장 = 📸 스냅샷 A

- 🚨 **신규 등록은 사진 1장 필수**(08-05 배포). ⛔사진 자동 첨부는 4경로 전부 차단(다시 시도하지 말 것)
  → **대표가 브리프 「사진 후보」에서 1장을 골라 직접 올린 뒤** 저장한다. (대표 부재면 여기서 멈추고 대기.)
- 저장 전 **폼 전체 스크린샷 + 프리필 텍스트**를 보관 = **스냅샷 A** ("제품이 혼자 만들면 여기까지"의 증거).
- 저장·검증·slug·소유권 = [[collab-brandpage-creation-basic]] §4·§6 그대로.

## ④ enrich 이어달리기 — 후보 선별 (유료 0콜)

[[collab-page-enrich]] ①진단 → §②-B 후보 랭킹(활동 10·콜라보 10) → §③-A **아티팩트 후보 페이지**로 대표에게.
⚠️ **리서치는 ①에서 이미 했다 — 재수확하지 말고 브리프·수확물을 재사용**한다(이 스킬의 존재 이유).
⛔ ③은 하드 게이트 — **대표 픽 없이 prod 수정 금지.**

## ⑤ 사진 전체 회수 + 초안 수정

- 대표가 고른 게시물의 사진을 폴더로 회수 — 기법 정본 = [[collab-page-enrich]] §④-B(61장 0실패 실증).
- 초안 텍스트 수정·보완 = §④ 폼 조작 정본(네이티브 setter·칩 Enter·임시저장 배너 함정 포함).

## ⑥ 대표 마무리 → 끝 = 📸 스냅샷 B

대표가 회수 폴더에서 사진을 골라 업로드 → 저장. ⑤재검증 보고([[collab-page-enrich]] §⑤ — DNA 영향 여부 포함).
**스냅샷 B**(최종본)와 A의 격차를 한 줄로 보고한다 — *"사람 손이 얼마나 들었나 = 이 영업을 몇 곳까지 감당하나."*

## 기존 스킬과의 관계

- [[collab-brandpage-creation-basic]] **모드 A**(순수 제품 생성)는 **"고객이 혼자 만들면"의 하한 측정용으로만** 남는다.
  ⚠️단 사진 필수(08-05) 때문에 모드 A도 저장하려면 사진 1장이 필요해졌다 — 측정만 하고 저장 안 하는 용도로.
- [[collab-brandpage-creation-basic]] **모드 B는 이 스킬로 대체**된다(모드 B 스스로 "정본은 enrich"라 선언한 상태였다).
- [[collab-page-enrich]]는 **이미 발행된 소개서 단독 보강**용으로 계속 유효 — 이 스킬은 그걸 제작 흐름에 편입한 것.

## 금지·비용 요약

- 유료 콜 = 위저드 1회(합 ~100원). **대표 승인 후에만.** 콜 상한 4(검색1+재시도2+생성1).
- ⛔ 동의 전 브랜드에 전량 수확 금지 / 인스타 로그인·우회 금지 / 사진 자동첨부 재시도 금지 / 대표 픽 전 prod 수정 금지.
- 보고: 브리프(①) → 승인 → 스냅샷 A(③) → 후보 페이지(④) → 재검증 + A/B 격차(⑥).
