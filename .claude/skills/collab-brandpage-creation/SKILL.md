## ⭐먼저 — 어느 모드인가 (필수)

두 가지 모드가 있고 **작업 시작 전에 반드시 어느 쪽인지 정한다.**

| | **모드 A — 순수 제품 생성** | **모드 B — 컨시어지 보강** |
|---|---|---|
| 정의 | **우리 웹 기능만으로** 생성. 사람 리서치 0. | 제품 생성 + Claude가 브라우저로 사장님 목소리 리서치 보강 |
| 별도 탭 크롤·기사검색·캡션 수집·사진 수집 | ❌ 안 한다 | ✅ 한다 |
| 손대는 것 | 위저드 선택 + 프리필 확인 + 저장. 위저드가 준 것만. | 위 + 2단계 리서치로 빈 섹션 보강 |
| 결과물 의미 | "사장님이 우리 사이트에서 혼자 만들면 나오는 것" = **제품 품질 실전 샘플** | 사람 손이 닿은 최대 품질 = **선물 최적화** |
| 언제 | 기능 검증·양산·다수 일괄 제작 | 특별히 공들일 소수, 자동 결과가 빈약할 때 |

**기본 규칙: 대표가 모드를 명시하지 않았으면 시작 전에 물어본다** —
"이거 순수 제품 기능만으로 만들까요(모드 A), 아니면 사장님 목소리까지 리서치해서 보강할까요(모드 B)?"
`/collab-ab-test`의 A/B 실험과는 다른 개념이다(그건 품질 측정용 2버전 비교, 이건 제작 방식 1택).

→ **모드 A면 "2단계 — 사장님 목소리 리서치"를 통째로 건너뛴다.** 1단계 생성 후 프리필 확인 → 바로 4단계 저장.
   단 "위저드가 준 press 링크를 저장에서 누락하지 않기"는 A에서도 지킨다(추가 수집이 아니라 누락 방지).
→ **모드 B면 아래 전체 절차를 따른다.**

## 핵심 테제 (두 모드 공통 배경)

**소개서 품질은 사장님 목소리를 얼마나 회수하느냐에 달렸다.** 자동 크롤은 원래 공식 문서(보도자료·매거진)에 의존하고 사장님이 직접 쓴 글(인스타 캡션·바이오·예약 플랫폼 소개문)을 놓쳤다.
그 격차의 상당 부분은 이미 제품에 코드화됐다 — **이 스킬의 역할은 "전부 수동 작성"이 아니라 "자동이 못 가져온 것만 메우기"다.**

| 재료 | 지금 상태 |
|---|---|
| 인스타 **바이오** | ✅ 자동 (서버가 봇 UA로 fetch — `src/lib/instagram.ts`) |
| 보도기사 **본문** | ✅ 자동 (`fetchArticleExcerpts`) |
| 홈페이지 | ✅ 자동 (딥리드 — 확약된 홈페이지를 서버가 최대 10p 순회, Gemini 콜 불변) |
| 인스타 **게시물 캡션** | ⚠️ **제품은 못 한다 / 컨시어지는 08-02부터 전량 가능**. 대표 세션으로 그리드 열거 + 내부 웹 API → 캡션 전문·작성일·태그계정·공동작성자. **사람(브라우저)의 남은 핵심 가치** |
| **사진** | ❌ 제품은 크롤 안 함. 컨시어지는 **선택 게시물 전 슬라이드 원본 URL을 캡션과 같이 받아** 폴더로 회수(0단계) — ⛔단 **소개서 폼 자동 첨부는 불가**(브라우저 4경로 차단, `collab-page-enrich` §④-B) |
| 예약 플랫폼 소개문·지면 매체 | ❌ 수동 |

절차: **0단계 준비 → 위저드로 베이스 생성 → 격차 확인 → 리서치·보강 → 저장·검증 → 리포트 자가검증 → 소유권 이전.**

### 폼에 자동으로 채워지는 것 (`applyWizard`, `register/page.tsx`)

저장 전에 아래가 이미 채워져 있다 — **덮어쓰지 말고, 빈 곳·틀린 곳만 손댄다.** `✨ 미리 채웠어요` 배지가 AI 초안 표시다.

상호 · 한두 문장 소개 · 자세히 소개 · **지역/상세주소/인스타/홈페이지/지도 링크** · 키워드 칩 ·
활동 힌트 · 콜라보 힌트 · 선택 블록 힌트(최대 2) · 찾는 파트너 힌트 ·
**함께하고 싶은 콜라보 칩(필수) + "이런 콜라보를 제공할 수 있어요" 텍스트**(`offersHint`) · `enrichment` 스냅샷.

- 프리필은 **never-overwrite** — 이미 값이 있으면 안 덮는다.
- 자세히 소개가 채워지면 상호 옆 버튼이 **`✨ 초안 다시 받기`**로 바뀐다(= enrichment 있는 소개서 전용, 07-22 정책). 다시 받기는 씨앗+사실게이트 통과 칩을 재료로 **재크롤 연동**된다.
- 위저드가 초본을 채우는 순간 🎉 축하+사진 유도 얼럿이 1회 뜬다(정상).

→ **모드 A는 여기까지.** 프리필 확인이 끝나면 2단계를 건너뛰고 **4단계(저장)로 바로 간다.**
→ **모드 B는** 비어 있거나 사장님 목소리가 안 들리는 섹션을 2단계에서 보강한다(전 섹션이 충분하면 리서치 생략 — 과잉 개입 금지).

### 분류 규율 (07-27 enrich 정책에서 증류 — 사람이 쓸 때도 같다)
- **활동 vs 콜라보 판별**: *"누구와 함께"가 붙어야 성립하면 콜라보다.* 협업·공동제작·입점·팝업 참여·페어·외부 기관 수업은 **[활동]이 아니라 [콜라보]**.
- **활동 승격 기준**(🔄08-02 개정 — ~~반복되는 것만~~ 폐기): ⭐**'이 브랜드다움이 드러나는가'**가 기준이다.
  정기 프로그램·대표 메뉴·상시 서비스가 1순위지만 **자체 기획 팝업·일회성 행사도 매력과 가치가 보이면 활동**이다.
  반복은 자격이 아니라 **순위 가중치**. ⛔단 유통기한 정보를 걷어내면 남는 게 없는 글(날짜·가격·마감 공지뿐)은 제외.
  ⚠️**콜라보 경계는 그대로** — 상대가 있으면 일회성이든 아니든 콜라보다(가르는 축은 반복이 아니라 **주최**).
- **협업 산출물을 상시 제품처럼 쓰지 않는다** — 팝업 협업으로 한 번 낸 향수를 "향수까지 갖추고 있습니다"로 쓰면 틀린 문장.
- **주체 확인** — 제3자가 이 브랜드를 *소재로* 만든 것(소설·기사)은 이 브랜드의 활동이 아니다 → [소개된 곳]으로.
- **거절 목록 방어** — *"유료 홍보·체험단 문의는 받지 않습니다"*를 [원하는 협업]에 넣으면 정반대 뜻이 된다. 부정문은 통째로 건너뛴다.
- **[고객]은 사람 집단만** — 감정·관심사·수업 내용(마음공부·불안·뜨개질)은 고객이 아니다. 판별: *"~하는 분들"을 붙여야 말이 되면 그건 주제다.*
- **충돌 시 사장님 글 승리**: 크롤(제3자 문서)과 사장님 직접 작성 텍스트가 충돌하면 사장님 쪽을 따른다.
- **작은 숫자 자랑 금지**: 팔로워 수 등은 자랑이 되는 규모일 때만 숫자 지표로 승격한다.
- **링크는 정직하게 표기**: '소개된 곳'은 언론만이 아니라 콜라보 상대의 글·블로그 후기·매거진·SNS 공식 게시물 전부 후보다. 단 언론이 아닌 건 **"블로그 후기"처럼 그대로 적는다**. 지면 매체는 링크 없이도 유지한다("웹에 없음 ≠ 실재 안 함").

### 보이스 (정본: `collab5-Obsidian/2_Areas/브랜드-보이스.md`)
- **해요체.** 격식체 남발 금지, 장식 따옴표 남발 금지, 맞춤법 점검.
- **현재형 원칙 (§7)**: 지금도 계속되는 일·상태는 **현재형/현재진행형**(`~하고 있어요` / `~이어가고 있어요`). 과거형은 **정말 끝난 사건에만**.
  - ❌ "2013년에 시작했어요" → ✅ "2013년에 시작해 지금까지 이어가고 있어요"
  - 적용 우선 3섹션: **자세히 소개 · 활동 · 콜라보**
  - 콜라보는 한 항목 안에서 시제 분리: 협약·행사 등 *사건*은 과거형, 그 결과로 *지금 하는 일*은 현재형.
  - 🚨⭐**완결형도 같이 막는다**(08-02 대표 지시, AI크롤 결과에서 나옴) — `만듭니다`·`완성했습니다`·`구축했습니다`·
    `마련했습니다`·`정착시켰습니다`는 문법상 현재형이어도 **한 번에 끝낸 것처럼** 읽혀 브랜드가 멈춘 인상을 준다.
    ⛔`계기를 만듭니다` → ⭕`만들어 가고 있습니다` / ⛔`가이드를 완성했습니다` → ⭕`완성해 가고 있습니다`.
    **문단을 닫기 전에 "이 일이 지금도 계속되나?"를 묻고 서술어를 고른다.**
- **어미 = 기능 기반 혼합체(자세히 소개 한정, §5)**: 믿음·확정 선언 `~합니다` / 이유·부연 `~이에요` / 지향 `~바랍니다`.
  합니다만 연속=사보, 에요만 연속=수다. **한 줄 소개는 예외 — 언제나 `~하고 있어요`.**
- **1인칭 사장 시점**: 주어는 저희/우리 또는 생략. 브랜드명을 문장 주어로 쓰지 않는다('저희는' 매 문장 반복도 금지).
- **Why가 한 번은 보이게(§1)** — 단 구체에 뿌리내린 Why만. 모든 문단을 Why로 시작하지 않는다.
- **상투어 금지**: 믿습니다·응원합니다·빛나는·소중한·특별한·함께 성장 등.
- 🚨⭐⭐**칸마다 규칙이 다르다** — **자세히 소개·시작 이야기**는 3~5문장 서사 허용, **활동·콜라보 desc는 한두 문장 사실 기술**이다.
  짧은 칸에는 아래 '의미로 닫기'를 적용하지 말고 `~하고 있어요`·`~했어요`로 딱 자른다.
  ⛔`~하는 자리를/시간을 만들었습니다` 같은 **명사화 금지**(의미는 동사로 담는다). 08-02 캔앤코르크에서 실제로 낸 사고다.
- ⭐⭐**닫는 문장은 '의미'로 — ⚠️자세히 소개·시작 이야기 전용**(08-02 대표 직접 퇴고. 정본 = [[브랜드-보이스]] §9 · `collab-page-enrich` §②):
  ⛔"빛나는 미래를 응원합니다"(상투어) / △"매번 새로운 주제를 정해 진행했어요"(사실에서 멈춤 — **얇다**) /
  ⭕"…오며가며 만난 사람들이 편하게 대화하는 **자리를 만들었습니다**"(그래서 무엇이 생겼는지).
  ⭕는 감정어를 얹는 게 아니라 **그 자리에서 실제로 생긴 것**에 이름 붙이는 것 — 근거 없으면 사실로 끝낸다.
  🔎점검법: 각 항목의 **마지막 문장만 모아 읽어라.** 전부 사실로 끝나면 얇다.
- ⭐**경험이 먼저, 제품은 그다음** — 특히 한 줄 소개. "무엇을 파는가"가 아니라 **"사람들이 왜 여기 머무는가"**.
  읽는 사람은 콜라보 상대라 매력과 *함께할 가능성*이 느껴져야 한다.
- ⭐**사람이 문장 가까이에** — 사람들이·이웃과·손님들과. 공간·제품만 나오는 문단은 정확해도 차갑다.

## 4단계 — 저장·검증

- 저장 전 폼 전체 값을 DOM으로 **전수 확인** (input/textarea `.value`, 칩 ✓ 상태).
  ⚠️textarea는 placeholder(회색 예시)와 value를 혼동하지 말 것 — 반드시 `.value`로 판정.
- **저장 전 마지막 체크**: **`검색에 보이기`가 켜져 있는가**(07-31부터 토글은 이것 하나).
  컨시어지 제작분은 **ON이 기본** — 홈·검색 노출 조건이 `search_visible ∧ status=active`라, 꺼두면 어디에도 안 나온다.
  ⭐이 토글은 이제 **"콜라보 제안을 받겠다"는 뜻까지 겸한다** — 사장님께 넘길 때 그렇게 설명할 것.
- 제출이 소리 없이 막히면 **빈 필수 항목**(상호·콜라보 칩)이 원인 — 토스트 + 해당 칸 스크롤로 표시된다.
- 저장 버튼은 read_page ref 또는 **좌표 실클릭**(재클릭 금지 — 이중 생성). `location.href`로 결과 검증.
- 저장 후 `/m/{slug}` 재조회로 전 섹션 노출 확인.

### 🔗 slug 규칙 (옛 "랜덤 m-xxxxxx"는 반만 맞다)
`slugify()` = `src/lib/actions.ts:78`. **ASCII 슬러그가 3자 이상이면 그걸 쓰고**, 한글 상호처럼 3자 미만으로 줄면 그때만 `m-` + base36 6자로 폴백한다. 중복 검사가 없으니 **저장 직후 실제 slug를 즉시 기록**할 것.

### 🚨 저장이 안 될 때 — 원인은 둘뿐이다
편집 폼은 열리는데 `수정 완료`가 `/m/{slug}`로 안 넘어가고 `/register?edit`에 머문다면(POST `net::ERR_ABORTED`, DB 미변경, 에러 표시 0) — **클릭 기법·사진 payload 탓이 아니다.**
1. **브라우저 쓰기 세션 만료** → 0단계 ② 대로 대표 크롬 fresh 세션으로.
2. **미소유(비회원 생성) 소개서** — `/my`에 안 뜨면 대표 계정 소유가 아니다(`/search`엔 떠도 `/my`에 없으면 미소유 신호). 저장이 소유자 체크로 막힌다.
   → **대표가 SQL로 먼저 귀속**(07-25 개명 반영본 — 옛 `makers`/`owner_uuid`로 쓰면 실패):
   ```sql
   UPDATE brands SET owner_user_id = (SELECT owner_user_id FROM brands WHERE slug='m-1vv8kj')
   WHERE slug = '<target>';
   ```
⚠️ **오귀인 주의**: 사진은 Storage URL이라 payload가 작다. 저장 실패를 사진·블록 탓으로 돌리지 말고 **먼저 세션·소유권을 의심**한다.

### 폼 조작 정본 (대표 크롬 fresh 세션)

## 6단계 — 소유권 넘기기 (대표 SQL · 07-31 갱신)

제품에 **양도·연결해제 기능이 없다.** 넘기려면 DB에서 직접. 정본 런북 = vault [[소개서-비번-소유권-런북]].

| | `owner_user_id` | 상대가 할 수 있는 것 |
|---|---|---|
| **A. 비번만 설정** | 내 계정 유지 | 비번으로 **수정만**. 상대 `/my`엔 안 뜸 |
| **B. 소유권까지 해제** | `NULL` | 수정 + **자기 계정에 연결(claim)**. 진짜 "넘겨주기" |

**"페이지를 준다"는 대부분 B다.** A만 하면 `claimMakerAction`이 "이미 다른 계정에 연결된 소개서예요"로 막아 상대가 영영 못 가져간다.

```sql
-- ③ 비번 설정 (해시 = 솔트 없는 SHA-256 hex 64자, 앱 lib/hash.ts와 동일)
update brands
set edit_password_hash = encode(sha256(convert_to('원하는_비밀번호','UTF8')),'hex')
where slug = '여기에_slug';

-- ④ 검증: 비번_일치 = true, 해시길이 = 64여야 정상
select edit_password_hash = encode(sha256(convert_to('원하는_비밀번호','UTF8')),'hex') as 비번_일치,
       length(edit_password_hash) as 해시길이
from brands where slug = '여기에_slug';

-- ⑤ 소유권 해제 (B안일 때만)
update brands set owner_user_id = null where slug = '여기에_slug';
```
- ⚠️ **비번과 소유권 해제는 한 번에 둘 다** — `owner_user_id`만 비우고 해시가 없으면 **영영 수정 불가**가 된다.
- ⚠️ **이중 해싱 사고 주의**: 로컬에서 만든 해시를 `digest()`로 또 감싸면 "64자리 해시를 비번으로 치면 통과"하는 상태가 된다. 한 방식만 쓸 것.
- ⚠️ 앞뒤 공백 금지(앱이 `.trim()` 후 해시). 가입 비번 규칙(8자·특수문자)은 여기 **적용 안 됨**.
- **SQL 실행은 대표가 Supabase SQL Editor에서 직접.** 세션은 쿼리만 제공한다.
- 전달 = **링크 + 비번** 두 개. 상대는 `/m/{slug}` → [수정] → 비번. 문구는 vault [[마케팅-실행]] §카톡 스크립트 B.
